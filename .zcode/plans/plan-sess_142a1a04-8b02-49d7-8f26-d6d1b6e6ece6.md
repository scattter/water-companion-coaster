# 网页蓝牙配网与管理员设备管理实施计划

方案可行。用户侧收敛为：**注册/登录 → 点击添加杯垫 → 选择蓝牙设备并按系统提示配对 → 输入 Wi-Fi → 自动完成联网和账号绑定 → 设置空杯。** 服务器地址由管理员维护，普通用户不填写，也不再手输八位绑定码。

## 一、确定本次边界

- 首版支持具备 Web Bluetooth 能力的 HTTPS 浏览器，优先验收 Android Chrome 和桌面 Chrome；运行时检测能力，不支持时明确提示。
- 管理员配置的是**设备 API 服务地址**，例如 `https://api.example.com`。沿用固件现有 origin 格式，不带 `/api` 路径，具体接口由固件追加。网页自己的 API 请求仍保持同源。
- 地址初始可取网站部署地址，管理员可修改。修改后在设备下一次蓝牙配网或重配时下发，已联网设备不会立即自动切换。
- 新地址必须连接同一套账号、设备凭证和绑定数据。支持同一服务更换域名或入口，本次不做两个独立平台之间的设备迁移。
- 保留一账号一台杯垫。OTA、多设备管理及原生 App 不在本次范围内。

## 二、先补齐两个必要约束

### 1. 服务器地址必须能被设备验证

当前设备访问服务器会携带长期 token。仅在网页上隐藏地址输入框，不能阻止其他蓝牙客户端下发假地址。

采用**服务器签名的配网授权**：部署时生成 P-256 签名密钥，私钥作为部署 secret 保存；出厂时通过 USB 写入部署标识及公钥。管理员仍可自由修改该部署的服务地址，无须为改域名重新烧录固件。

授权绑定设备编号、本次设备随机挑战、目标地址、操作 ID、配置版本和有效期。杯垫先验签，再向目标发送设备凭证。公钥不能通过普通蓝牙入口替换；未安装信任配置的旧设备需要一次 USB 升级和配置。

### 2. 转绑必须隔离前任用户数据

目前记录只按设备编号保存，直接解绑再绑定会让新账号获得旧记录。新增“绑定批次”，事件生成时就记录所属批次；旧账号历史、设备离线补传、状态和控制命令均按批次隔离，不能按上传时的当前主人重新归属。

## 三、实施步骤

### 第一步：数据库迁移、管理员权限和管理页面

涉及现有 `server/src/db.ts`、`auth.ts`、`provision-registry.ts`，新增独立管理员路由及网页组件。

- 增加可重复执行的数据库版本迁移，建立管理员角色、服务配置、配网操作和绑定批次等数据结构。
- 默认注册账号都是普通用户；提供本机命令将明确指定的已有账号设为管理员，不采用“第一个注册者自动成为管理员”。
- 管理员页面提供设备登记、登记清单导入、设备登记/绑定状态查询、设备 API 地址配置。
- 复用现有登记清单校验和事务导入：同编号同凭证可重复提交，冲突拒绝；不覆盖已有 token 或账号归属。
- 单台登记支持输入编号与 token，服务端立即计算哈希，仅保存哈希；批量优先上传现有哈希清单。列表、日志和响应均不回显原始 token。
- 服务地址统一校验 HTTPS、长度及 origin 格式，保存配置版本。普通用户不能修改。
- 每个管理员 API 都执行服务端权限检查，并沿用现有 Cookie、同源校验和限流。

### 第二步：出厂配置与云端自动绑定协议

- 保留现有“生成编号/token → USB 写入”的出厂方式，补充部署公钥写入、脱敏身份读回核验及登记清单输出。管理员从网页完成线上登记，不再需要到服务器执行导入命令。
- 网页连接 BLE 后读取设备编号、协议版本及本次随机挑战，向同源后端申请短期一次性配网授权。
- 签发前检查设备已登记、账号设备限制和当前归属：未绑定允许认领；属于当前账号允许重新配网；属于其他账号返回“请原账号先解绑”。
- 网页将 Wi-Fi 信息、管理员配置的地址、签名授权和绑定票据一起发送给杯垫。长期设备 token 不进入浏览器或蓝牙协议。
- 杯垫联网后用原有设备凭证兑换票据。服务端在事务中再次检查归属并完成认领，避免并发抢绑；同一操作重复提交返回原结果。
- 区分“收到配置、连接 Wi-Fi、验证云端、绑定完成、配置保存完成”。只有云端绑定和设备持久化均确认后，网页才显示成功。
- 对响应丢失保留可查询的操作结果，不让用户因为超时重新认领或误判失败。

### 第三步：固件 BLE 与可恢复配网流程

复用 `network.c`、`coaster.c`、`storage.c`，新增 BLE 服务模块及配网状态机。

- 使用 ESP32 Arduino 包内已有 BLE 库，提供设备信息、配置写入、进度读取/通知；协议包含版本、操作 ID、分片序号、长度限制和超时。
- 首次未配网自动开放窗口，之后沿用 BOOT 长按三秒开启限时配网。窗口结束后同时拒绝已有连接继续写入。
- 使用 BLE Secure Connections 加密，并结合设备屏幕/按键完成需要的配对确认。Wi-Fi 密码和票据不输出到日志。
- BLE 回调只收包和提交任务，由网络任务执行联网；正常配网不重启，便于把进度直接反馈给网页。断线后允许重连读取结果。
- 将 Wi-Fi 和服务器地址作为一组候选，只有云端验证、绑定和保存完成才正式生效。明确的网络失败恢复原配置；云端可能已经成功的情况先恢复操作结果，不能盲目回滚或重新绑定。
- 试用候选期间暂停常规事件上传和云端控制命令，避免把旧数据发到尚未确认的目标。
- 保留原身份、称重标定和事件分区。配网事务用独立版本化存储，事件格式新增绑定批次并提供旧格式兼容读取。

### 第四步：网页添加向导、重新配网和解绑

主要改动 `web/src/App.vue`、`DeviceSetup.vue`、`api.ts`，新增 `DeviceOnboarding.vue`、`bleProvisioning.ts`、`AdminDevices.vue`。

- 添加设备页面以蓝牙向导为主；选择器直接由用户点击触发，避免异步请求使浏览器丢失授权手势。
- 展示设备、Wi-Fi 表单和进度。区分用户取消、蓝牙断线、密码错误、云端不可达、未登记、票据过期和他人已绑定，提供对应重试。
- 配网成功刷新会话，再进入现有空杯设置；同账号更换 Wi-Fi 沿用同一向导和绑定批次。
- 设备设置中增加解绑确认。原账号解绑时终止归属、废止旧票据/绑定码及待执行命令，保留出厂身份；新用户成功绑定后重新设置自己的空杯。
- 原用户历史仍归原用户，新用户只能读取自己的绑定批次。浏览器退出登录、解绑或切换账号时清理连接和临时状态，忽略迟到回调。
- 现有热点和八位码保留为折叠的兼容入口，但共用新的归属检查；没有可信服务地址的设备不能依赖该入口绕过新流程。

### 第五步：兼容迁移与验证

- 已有明确归属的云端记录迁移到原账号对应批次；无明确归属的历史保留隔离，不自动赠予下一位用户。
- 旧格式离线事件保留处理，不按新主人归属。缺少绑定批次能力的旧固件在转绑前要求升级，避免静默泄露历史。
- 不覆盖当前工作区已有的未跟踪 JS 测试文件。
- 更新协议、出厂操作、管理员初始化、部署签名密钥备份及用户配网说明。

## 四、验收标准

1. 管理员登记后，新设备可由用户在网页完成 BLE 配网、地址下发和账号绑定，无须输入设备 token、地址或八位绑定码。
2. 管理员改地址后，下次重配使用新地址；非授权地址、篡改签名和过期操作在设备发送长期凭证之前被拒绝。
3. 已属于其他账号的设备不能被认领；原账号解绑后可以转绑，新用户看不到旧用户历史和离线补传数据。
4. 错误 Wi-Fi、TLS 失败、蓝牙断线、重复提交、云端成功但响应丢失及保存中断电均有明确可恢复结果。
5. 完成服务端权限/迁移/并发绑定测试、BLE 协议与状态机测试、前端类型检查和构建、固件完整编译；新增可重复运行的前端 BLE 逻辑测试。
6. 真机验证 Android Chrome 和桌面 Chrome 的配对、Wi-Fi/BLE 同时运行、内存及固件体积、断电恢复。自动化通过与真机未验收分别记录，不以模拟测试代替实物结论。

**实施顺序：云端数据与权限 → 管理入口及协议 → 固件 BLE → 网页向导 → 迁移和端到端验收。** 本次目前仅完成只读分析和计划，尚未修改代码。
