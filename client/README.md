# 饮水陪伴客户端

Tauri 2 + Vue 3。像素水豚直接在 Mac 顶部状态栏里播放工作、打盹、喝水和举瓶动作，旁边显示今日饮水量。左键在图标下方展开无标题栏的圆角浮窗，再次点击图标、点击外部或按 Esc 收起；切换应用或桌面空间也会收起。右键打开快捷菜单。浮窗收起后，状态栏动画和原生同步继续运行，只有“退出饮水陪伴”会停止程序。

Windows 10/11 x64 延续桌面功能，驻留任务栏右侧通知区域。安卓 8.0+ arm64 提供完整普通用户流程和原生桌面小组件。桌面端可从“饮水记录”按日期查看统计和饮水、补水明细，注册、配网和撤销记录仍从“打开网页与设备设置”进入；安卓直接复用 `web/` 的这些页面，管理员管理功能继续使用网页。

## Windows

运行 `water-companion-windows-x64-setup.exe` 为当前用户安装。程序没有商业代码签名；首次安装时 Windows 可能显示发布者未知提示。未安装 WebView2 的电脑需要联网，由安装程序下载微软运行时。

启动后在任务栏右侧通知区域显示水豚，若系统将其折叠，可从上箭头区域拖出。Windows 托盘不显示图标旁文字，悬停提示和详情面板显示饮水量与连接状态。左键切换详情，右键可打开详情、设置或退出；失焦、Esc 和关闭操作收起面板。重复启动会激活已有实例。

面板按托盘所在屏幕的工作区及缩放定位。登录会话按服务器保存在 Windows 凭据管理器，设置保存在本机应用配置目录。空闲检测使用 `GetLastInputInfo`，锁屏/解锁及休眠恢复通过 WTS 和系统电源消息处理，沿用桌面状态机的恢复基线规则。

## 安卓

安装 `water-companion-android-arm64.apk`，按手机提示允许本次安装来源。首次打开填写 **HTTPS 服务根地址**，然后注册或登录。安装版保留证书验证并禁止明文 HTTP；HTTP 仅用于调试版本。用户流程包括蓝牙配网并绑定、旧设备绑定码、日常空杯设置及回执查询、查看和撤销记录、更换 Wi-Fi、解绑。

选择杯垫时按系统提示授予蓝牙权限；Android 8–11 扫描还需要定位权限和系统定位开关。配对码以杯垫屏幕显示为准。蓝牙由 Kotlin 执行扫描、选择、系统配对及串行 GATT 读写，网页原有 `BleTransport` 继续负责分片与协议解析。配网以设备持久保存及云端确认作为完成条件；重启后恢复原操作编号查询，不能把断开蓝牙当成成功。

应用内水豚使用已有状态机，只在前台播放。切到后台停止高频同步及动画；系统配对界面临时覆盖应用时允许正在进行的配对读取完成。返回后重新建立基线，不补播后台动作。返回键依次关闭键盘、提示弹窗、下拉菜单、设置弹层或子页面，首页返回桌面。

安卓顶栏点击用户名可退出登录；“设置”菜单集中提供服务设置、杯垫设置（未绑定时为添加杯垫）和添加桌面组件。饮水趋势内左右滑动日期条可浏览前后七天，点击日期切换统计与明细，日历可直接选择更早日期。趋势显示截至所选日期的七天；历史日期不触发水豚喝水动作，也不会替换桌面组件或桌面托盘的今日快照。网页和桌面记录视图提供前一天、后一天、日历与回到今天，三端都使用服务端时区分日，各端独立选择查看日期。

安卓 App 的添加组件说明及操作成功、失败、异常反馈使用可关闭弹窗，支持右上角关闭、“知道了”和返回键，不占用页面布局。提示在杯垫设置之上显示，关闭提示后继续当前表单或操作；设备状态、必要引导和等待进度保留在原位置。同一持续故障关闭后不会随自动轮询重复弹出，主动重试或恢复后再次失败可以重新提示。网页和桌面客户端保留原有提示方式。

在顶部“设置”菜单点击“添加桌面组件”，也可长按桌面从小组件列表添加“饮水陪伴”。组件默认 4×2，长按并拖动边框可自动切换布局：小尺寸（约 2×2）显示今日饮水量与工作水豚；中尺寸（约 4×2）左右排列水豚与统计，增加饮水次数和最近一次饮水；可用尺寸达到 250×190 dp 时显示喝水水豚和可上下滚动的有效饮水记录，达到 250×250 dp 时再显示近七天趋势。实际占用格数由手机桌面决定，较矮的 4×3 也能进入记录布局。各尺寸统一使用 12 dp 外边距、4 dp 内容间距和同一底栏文字样式。记录卡片的统计区按内容收紧，饮水量与水豚底部对齐；继续放大时由趋势和记录区域分配额外空间，记录行保持紧凑并隐藏滚动条，列表末尾显示“没有更多了~”，记录较少时尾注靠记录区域底部；无记录时仍居中显示空提示。窄高小卡片按水豚可见图案居中，最小高度时为统计和同步文字保留空间；左右边距与中尺寸卡片统一。点击卡片或“查看更多”打开应用，点击刷新图标尝试同步。所有组件共用当前账号。

中、大尺寸将饮水次数合并到标题，例如“今日饮水 6 次”，次数数字以主题绿色、加粗和轻微放大突出，不再单独占用“已喝 6 次”一行。尚无统计数据时不显示次数；离线跨日仍保留快照日期。

点击刷新后图标旋转，等待任务启动时显示“等待刷新…”，同步期间显示“正在刷新…”，完成或失败后停止并恢复同步信息。动画由桌面的原生进度控件驱动，快速返回时至少保留 600 毫秒反馈；刷新中重复点击不会重复提交任务。手动刷新不等待联网条件，离线时也会结束本次尝试；后台周期任务仍保留联网约束。

Android 12 及以上由系统根据可用尺寸选择布局，旧版按横竖屏尺寸分别适配。组件沿用现有饮水快照，记录排除补水和已撤销项，趋势只覆盖快照日期及之前六天；未登录、等待同步及无记录时显示对应空状态。离线跨日保留快照日期与同步日期，不把旧数据标记为“今日饮水”。

组件使用独立的当天快照，不显示页面选择的历史日。离线保留带日期的上次快照，退出账号或切换服务器立即清除。前台同步后直接更新组件；后台仅使用唯一的 WorkManager 15 分钟周期任务，系统省电、网络及厂商限制可能延后执行，不保证整点刷新，不添加后台喝水通知。删除最后一个组件或退出登录后取消周期任务。

API 和小组件共用 Kotlin 数据层。会话经 Android Keystore 的 AES-GCM 加密并绑定服务器地址，令牌不会进入页面。配网及空杯操作编号按服务器、账号和绑定保存，不保存密码或配网票据；身份变化使旧请求失效。应用禁止系统备份登录数据。

## Windows / 安卓打包

在仓库根目录执行：

```sh
npm run build:client:windows
npm run build:client:android
```

Windows 原生构建需要 MSVC Build Tools、Rust `x86_64-pc-windows-msvc` 目标及 NSIS；Mac 交叉构建使用 `cargo-xwin`、同一 Rust 目标、LLVM 和 NSIS。脚本可通过 `LLVM_BIN` 指定 LLVM，默认复用本机 Android NDK 的 LLVM；`cargo-xwin` 首次会下载微软 CRT/SDK，默认只构建 x64。

安卓需要 JDK 17、Android SDK 36 / Build Tools 36.0.0、NDK 27.2.12479018 和 Rust `aarch64-linux-android` 目标。可设置 `JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME`；Mac 默认使用 `~/Library/Android/sdk` 和 Homebrew JDK 17。生成工程已保存在 `src-tauri/gen/android`，不要重新初始化覆盖自定义 Activity 和构建配置。

产物统一复制到 `output/client/`，同时生成 `SHA256SUMS.txt`。正常打包覆盖固定名称的安装包，不额外归档上一版本。历史安卓安装包备份已按要求清理。安卓脚本使用本地专用 PKCS#12 签名，密钥与密码保存在 Git 忽略的 `data/client-signing/`，文件仅本机用户可读写。请备份整个目录；后续更新保持同一 applicationId 和签名即可覆盖安装，丢失密钥需要卸载后重装。不要将密钥加入 Git 或分享给安装者。

原生安卓轻量检查（首次运行需已执行一次安卓构建以生成插件路径）：

```sh
cd client/src-tauri/gen/android
./gradlew :coaster-mobile:testDebugUnitTest :coaster-mobile:compileReleaseKotlin --no-daemon
```

## 使用

首次打开，填写已部署的服务根地址并测试连接，再使用现有账号登录。支持域名、IPv4、带方括号的 IPv6 和端口，例如 `water.example.com`、`http://192.168.1.8:3001`、`https://[2001:db8::1]:8443`。省略协议时使用 HTTPS，不需要 `/api`。注册、配网、空杯设置和历史记录管理通过“打开网页”进入现有网站。

服务端仍然校验 Host；客户端填写的入口需要与部署允许的地址一致。客户端保留证书验证，不跟随登录或 API 重定向。切换服务会取消旧请求、清除当前数据和旧会话，再登录新服务。

设置中可修改服务器地址、关闭自动休息或轻提醒。首次配置或需要登录时自动打开页面；已保存会话的日常启动只驻留顶部状态栏，点击水豚后再打开详情或设置。没有桌面悬浮卡片，也不显示 Dock 图标。

浮窗宽度为 340，高度随当前内容自动伸缩，切换页面或增减提示信息时同步更新。水豚动画与今日饮水量左右排列，明细位于下方。浮窗以菜单栏图标为中心，距图标下沿 4 个逻辑像素；靠近屏幕边缘时向内避让。详情、设置和重新打开应用均重新定位到图标；屏幕可用高度不足时缩短窗口，表单和较长内容可滚动。Mac 原生窗口负责圆角、阴影和跨屏定位，沿用现有页面与后台同步。

## 开发与检查

需要 Node.js 24、Rust 1.88 或更新版本，以及 Xcode 命令行工具。Mac 最低版本为 macOS 13。仓库根目录执行：

```sh
npm ci
npm run dev:client
```

`dev:client` 只启动客户端开发页面和原生应用，不启动项目后端；使用已部署的服务。首次原生编译需要下载 Tauri 依赖。相关轻量检查：

```sh
npm run check:client
npm run check:client:native
npm run test:client:native
```

安装包构建、签名和公证不包含在这些检查中。当前版本未添加自动更新或开机启动。

## 打包为 Mac 应用

仓库根目录执行 `APPLE_SIGNING_IDENTITY=- npm run build:client`，会构建前端和 Release 原生程序，并为本机使用进行 ad-hoc 签名。产物为 `client/src-tauri/target/release/bundle/macos/饮水陪伴.app`，可以复制到 Mac 的“应用程序”文件夹后双击启动，不需要运行开发服务。

默认面向执行构建的 Mac 架构；在 Apple Silicon 上生成 arm64 应用。此命令只生成 `.app`，不生成 DMG，也不做 Apple 开发者签名或公证。

## 开发更新与钥匙串授权

客户端读写、清除会话时均禁止钥匙串弹出系统授权窗口。无须配置开发证书；本地构建按可执行文件的指纹使用独立钥匙串条目，同一版本重启会恢复登录，重新构建或签名后需要重新登录。登录与退出只处理当前版本、当前服务器的条目，避免旧版本条目的访问权限阻塞新登录。

凭证继续保存在 macOS 钥匙串中，不扩大条目的访问权限。系统“登录”钥匙串被锁定等情况下，客户端提示检查钥匙串状态，不自动弹出授权窗口。

真实钥匙串回归检查默认忽略，需要本机已解锁的钥匙串时可运行 `cargo test --manifest-path client/src-tauri/Cargo.toml --locked --lib credentials::tests::current_build_credentials_do_not_touch_legacy_entries -- --ignored --exact`。该检查只创建并清理随机 `.invalid` 测试账号，覆盖保存、读取、更新、清除与旧版本条目隔离。

## 数据与角色规则

- 原生进程通过现有 `/api/auth/*`、`/api/dashboard` 和 `/api/health` 通信。会话凭证只保存在原生内存和 macOS 钥匙串，前端快照不包含凭证，密码不落盘。
- 默认每 5 秒同步一次；失败后按 10、20、40、60 秒退避。详情窗口关闭不影响同步。界面使用原生快照序号丢弃迟到数据，服务/账号切换会取消旧网络请求。
- 观察到当前杯垫从有杯变为无杯后，水豚转向电脑的另一侧喝水，保持到杯子放回；仅拿杯不会增加饮水量或重置提醒。首次连接、重连、唤醒或更换绑定后的第一批数据只建立基线，杯子原本不在杯垫上时不补播。设备异常或断线会结束拿杯动作。
- 当前绑定、未撤销、首次出现且发生于最近两分钟内的饮水记录仍触发 4 秒喝水动作，放回确认后完成这段动作再恢复工作/休息。同批记录合并播放，补水记录不触发。拿杯状态沿用设备心跳与客户端每 5 秒同步，可能有数秒延迟；短暂取放若没有被同步捕获，仍可在饮水记录到达时播放动作。
- 累计活跃 60 分钟没有新饮水时举瓶 4 秒，每轮只提醒一次；新有效饮水（包括旧补传）重置计时。电脑空闲达到 5 分钟时休息，锁屏、断网、设备离线或异常期间不累计提醒时间。
- 忙闲仅查询系统空闲时长；休眠/唤醒使用系统工作区通知，锁屏补充观察 macOS 分布式状态通知。不会监听按键内容、申请输入监控或上传忙闲数据。系统通知兼容性仍需实机验证，查询失败时保持安静待机。
- 当前进程断线时保留最后成功数据及同步时间；重新启动后需要恢复会话和同步数据。按服务端日期/时区展示，离线跨午夜不把旧数据伪装成当天数据。
- 本机设置保存在系统应用配置目录的 `com.watercompanion.client/preferences.json`，不含密码或 Cookie。退出账号会清除本机凭证；网络不可用导致云端注销无法确认时会明确提示。
