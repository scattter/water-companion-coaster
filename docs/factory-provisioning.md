# 出厂登记、管理员配置与蓝牙配网

新设备使用 `coaster-000001` 到 `coaster-999999`，每台一个编号、一份独立随机密钥。编号由操作员分配；已有设备继续使用原编号和凭证。以下流程不需要用户填写设备密钥或服务器地址。

## 1. 部署初始化（每个服务做一次）

按 [部署说明](../deploy/README.md)运行网站与 API，在网站注册管理员将使用的普通账号，再在服务器显式提升该账号的权限。不会把第一个注册者自动设为管理员。

配网服务使用独立 P-256 私钥签名，设备只保存公钥。非容器部署示例：

```sh
npm run provisioning-key -- --out ./data/provisioning-private.pem
```

工具创建受限权限的私钥文件，公开输出 `{deploymentId,publicKey}`。已有文件不覆盖；公钥为 `04` 开头的 130 位十六进制文本。将部署 UUID 与私钥文件路径配置到服务环境：

```dotenv
PROVISION_SIGNING_KEY_FILE=/实际路径/provisioning-private.pem
PROVISION_DEPLOYMENT_ID=工具输出的UUID
```

管理员初始化：

```sh
DB_PATH=/实际持久目录/coaster.sqlite npm run admin -- --username 已注册账号
```

重启服务加载签名配置，管理员重新读取会话后可进入“设备管理”。私钥不通过网页上传、不写入固件、不纳入 Git。数据库、部署 UUID 和签名私钥需要一起备份；不能为日常升级重新生成另一把密钥。

## 2. 逐台生成身份并通过 USB 写入

本机使用 Node.js 24。已有 `.env` 不覆盖。工具使用当前 `DB_PATH`，默认数据库为 `data/coaster-hardware.sqlite`。

```sh
npm run provision -- --id coaster-000001
```

工具生成 32 字节随机密钥，输出一条 `server` 命令。本机数据库只保存 SHA-256 哈希，原始 token 无法从哈希恢复。重复登记编号会被拒绝，不会重置设备凭证。

先按 [固件说明](../firmware/README.md)升级支持 BLE 的固件，保留 `partitions.csv`、关闭“擦除全部 Flash”。Arduino 串口监视器使用 115200 波特率、新行，发送实际工具输出并等待成功。以下仅为格式：

```json
{"cmd":"server","id":"coaster-000001","token":"本台设备实际生成的密钥"}
{"cmd":"trust","deploymentId":"部署UUID","publicKey":"部署公钥04开头的130位十六进制文本"}
{"cmd":"reboot"}
{"cmd":"factory-info"}
```

`factory-info` 用于核对持久化编号、凭证指纹和信任配置，不返回原始 token。每台写入相同部署的公开信任配置，但设备编号和 token 必须逐台独立。普通 BLE 不能修改身份或信任根。

新机不必用 USB 写服务器地址。管理员网页的当前地址将在用户蓝牙配网时下发；没有地址的新机不能先依赖热点旧流程联网。旧设备保留既有地址，USB `server url` 仍可用于受控调试。

出厂工具不会自动控制串口：输出命令由操作员发送。原始 token 应受控备份，不放到设备标签、用户二维码或操作截图中。

## 3. 管理员网页登记设备

推荐在本机导出不含原始 token 的登记清单：

```sh
npm run provision -- --export ./output/factory/batch-001.json --id coaster-000001
```

省略 `--id` 可导出所有符合六位编号规则的设备。文件只包含 `id`、`tokenHash`、`createdAt`；不会导出账号、绑定关系、饮水记录或服务器地址。输出不覆盖已有文件。

管理员登录正式网站，进入“设备管理”，上传此 JSON。也可单台填写编号和原始 token；服务端立即计算哈希，仅保存哈希，不在列表或响应中回显 token。

导入规则：

- 新编号登记为未绑定设备。
- 相同编号、相同哈希重复导入跳过，保留已有归属和历史。
- 同编号凭证冲突、多个设备共用凭证、非法数据，整个批次拒绝。

登记成功后立即生效，无需重启或重新部署。不要两边分别为同一个编号生成 token，不要用工厂电脑数据库覆盖线上库。原 CLI `--import` 仍可用于受控批量运维，但不再是正常网页登记的前置步骤。

## 4. 管理员设置设备服务器地址

在“设备管理”的服务器设置中填写 HTTPS origin，例如 `https://api.example.com`，不带路径、查询参数、账号密码或 fragment，最多 191 UTF-8 字节。设备自己追加 `/api/device/...` 路径。

地址可以与网站相同，也可以是连接同一后端的其他入口。网站自身仍访问同源 `/api`，不会把会话 Cookie 发送到管理员填写的任意地址。初始地址取部署时的 HTTPS `APP_ORIGIN`，之后以数据库中管理员的设置为准。

修改只影响下次蓝牙配网/重新配网，不会自动迁移所有在线设备。新入口必须保留原部署、签名信任、账号、设备凭证和绑定数据；更换独立平台不是本功能的范围。设备先验证签名授权，再向目标提交长期认证凭证。

## 5. 工厂标定与交付

整机完成后空载执行 `tare`，放上已知质量执行 `calibrate`，用其他重量复核。断电重启后应保持 `calibrated: true`。这些仍是工厂串口能力，不进入用户网页。

不要替最终用户绑定账号、设置工厂测试杯为空杯。测试 Wi-Fi 会保存，已配网设备再次进入配网需要正常启动后长按 BOOT 三秒。不能把按住 BOOT 上电的烧录模式当作配网。

## 6. 用户使用与转绑

1. 在支持 Web Bluetooth 的浏览器打开 HTTPS 正式网站，注册/登录。
2. 新机通电，或长按 BOOT 三秒打开限时配网窗口；网页点击添加杯垫，选择目标设备。
3. 按系统提示完成蓝牙配对，必要时输入杯垫屏幕上的配对码。此码属于蓝牙加密配对，不是旧的八位云绑定码。
4. 填写普通 2.4 GHz Wi-Fi，网页同时发送管理员配置的服务器地址和短期授权。
5. 等待“配置已保存、绑定完成”。只看到 Wi-Fi 连接成功或蓝牙写入成功不代表完成。
6. 放上自己的空杯，静置至少三秒，执行空杯设置并等待设备确认。

同账号换网沿用此流程，不更换绑定批次。已属于其他账号时提示原账号先解绑，重置 Wi-Fi 不会解除云端归属。原账号在设备设置中确认解绑，新用户再配网绑定并设置自己的空杯。旧用户历史和离线补传不能出现在新用户账号下。

不支持的浏览器会明确提示；首版不支持 iPhone Safari 的网页蓝牙。已预配可信服务地址的旧设备可使用折叠的热点/八位码入口，仍执行相同归属规则。

## 局域网联调与地址切换

USB `server url` 仍可设为 `http://192.168.1.10:3001` 这样的 RFC1918 私网 IPv4 origin，再 `reboot`。它仅用于受控网络，长期设备凭证没有 TLS 加密；正式交付与网页 BLE 签名入口都要求 HTTPS。不要填 localhost、127.0.0.1、0.0.0.0、网页静态端口或 `/api` 路径。

API 需监听杯垫可达的网卡，电脑和杯垫在互通网络，目标库必须登记同一身份。USB 改地址是工厂能力，不复制账号或历史；新 BLE 流程只支持同一部署更换入口。

## 7. 故障与恢复

- 未登记或凭证错误：管理员核对目标数据库、出厂编号和凭证指纹，不重复生成新 token。
- 服务器地址授权失败：核对设备部署 UUID/公钥与服务端签名配置，不关闭验签。
- Wi-Fi 密码错误或 TLS 失败：检查网络、证书和设备时钟，失败时保留原配置。
- 蓝牙断开/网页超时：重新连接并查询同一操作；云端可能已成功，不盲目再次认领。
- 升级前备份数据库。旧事件与主配置须按版本迁移，保留原分区，不擦除历史。

真实配对、Wi-Fi/BLE 共存、断电恢复和称重仍须真机验收；本地构建或模拟测试不能代替实物验证。
