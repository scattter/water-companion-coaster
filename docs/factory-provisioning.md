# 本机出厂登记与上线

新设备使用 `coaster-000001` 到 `coaster-999999` 的编号，每台一个编号、一份独立随机密钥。编号由操作员指定，`coaster-000000` 不使用。已有设备继续使用原编号和凭证，升级不会自动改号。

出厂登记分为三个位置：本机登记工具生成凭证，本机 USB 把凭证写进杯垫，线上数据库导入对应的凭证哈希。**只更新线上代码不会同步本机数据库；导入登记清单后，线上服务才能认证新杯垫。** 设备身份与服务器地址分开配置，登记不需要 URL，也不需要 `DEVICE_SERVER_URL` 环境变量；可选 `--url` 只为生成完整配置，不会连接远端服务器。

## 1. 在本机登记

使用 Node.js 24，在项目根目录安装依赖后操作。登记工具使用 `DB_PATH` 环境变量或根目录 `.env` 中的配置，默认数据库为 `data/coaster-hardware.sqlite`。已有 `.env` 不要覆盖。

```sh
npm ci
npm run provision -- --help
npm run provision -- --id coaster-000001
```

下一台改用 `coaster-000002`，依此类推；多台工厂电脑需要事先分配互不重复的编号区间，工具不会跨电脑自动协调编号。

命令生成 32 字节随机密钥，以 64 位十六进制文本输出单行身份 JSON：

```json
{"cmd":"server","id":"coaster-000001","token":"这里是工具实际生成的密钥"}
```

也可以附加 `--url https://你的正式域名`，一次生成包含服务器地址的完整配置；完整格式仍兼容旧固件。新分步格式需要固件 **0.5.1**，先上传新版固件再发送。

示例中的 token 是占位说明，写设备时必须使用实际输出的完整一行。本机数据库只保存 SHA-256 哈希。原始输出应单独受控保管，不放进 Git、设备标签、用户二维码、截图或普通操作台账。重复登记相同编号会拒绝执行，不会显示原密钥，也不会换掉原凭证。

## 2. 经 USB 写入对应杯垫

先按[固件说明](../firmware/README.md)烧录固件，保留 `partitions.csv`，关闭“擦除全部 Flash”。在 Arduino 串口监视器选择对应端口、**115200 波特率、新行（New Line）**。

1. 发送上一步输出的身份 JSON，等待 `ok: true`；仅设置编号和密钥，不更改已有服务器地址。
2. 单独发送服务器地址，例如 `{"cmd":"server","url":"https://你的正式域名"}`，等待 `ok: true`。这一步不需要重新提供编号和密钥。
3. 发送 `{"cmd":"reboot"}`，等待重启。
4. 发送 `{"cmd":"status"}`，核对 `cloudUrl` 为目标地址、`serverConfigured: true`。这只表示配置已加载，不代表线上认证成功。

`server` 命令可以只含 `url`，也可以只含成对的 `id` 和 `token`，或同时设置两组。已提供的字段不能为空或为 `null`；只传 `id` 或只传 `token` 会拒绝，原配置不变。新机只有身份、还未设置地址时，`serverConfigured: false`，不会发起云端请求。所有联网配置修改都需重启生效。

固件在未登记时可能使用基于 MAC 的默认编号，`server` 命令会写入选定的六位编号。不要把所有固件的默认值改成同一个固定编号。存在待处理记录的旧设备禁止随意改号，旧设备升级继续保留原配置。

整机装配后还需要空载 `tare`、已知质量 `calibrate` 和其他重量复核；重启后应保持 `calibrated: true`。空杯由最终用户登记，工厂不要替用户绑定账号。

## 3. 导出登记清单

单台登记和 USB 写入结束后，在同一本机数据库导出：

```sh
npm run provision -- --export ./output/factory/batch-001.json --id coaster-000001
```

批量完成后也可以不传 `--id`，导出本机所有符合六位编号规则的设备：

```sh
npm run provision -- --export ./output/factory/batch-002.json
```

相对文件路径以项目根目录为基准。工具会创建所需目录，文件只允许当前用户读写；已有目标文件不会被覆盖，下一批使用新文件名。`output/` 已被 Git 和 Docker 构建上下文忽略。

清单是版本化 JSON，只包含 `id`、`tokenHash`、`createdAt`，**不包含原始 token、账号、绑定关系、饮水记录或服务器地址**。不符合新编号规则的旧联调设备不会混入批量导出。同一编号已绑定时，导出的仍只是设备登记信息，不会把本机账号归属带到线上。

该文件用于授权设备身份，仍应通过受控方式交给服务器管理员；不要接受来源不明的登记清单。它不是原始密钥备份，不能拿来重新给杯垫写入 token。

## 4. 更新线上代码并导入

先按[部署说明](../deploy/README.md)备份线上数据库并更新服务，使线上具有新版登记工具。将本机导出的清单通过 SSH/SCP 等方式上传到服务器项目的 `output/factory/` 下，保留现有数据库持久卷。

使用项目的 Docker Compose 部署时，在服务器执行：

```sh
cd deploy
docker compose exec -T api node server/dist/provision.js --import - < ../output/factory/batch-001.json
```

`--import -` 从标准输入读取清单，`-T` 关闭容器终端分配；文件由服务器当前用户读取，不需要复制进容器或放宽文件权限。

如果未使用 Docker，在服务器项目根目录执行，`DB_PATH` 必须与运行中的 API 相同：

```sh
DB_PATH=/实际持久目录/coaster.sqlite npm run provision -- --import ./output/factory/batch-001.json
```

导入可以在 API 运行时执行，成功后不需要重启 API。工具会报告新增和跳过数量：

- 编号尚不存在：新增设备，保持未绑定。
- 编号和凭证哈希完全相同：跳过，保留线上已有账号归属、创建时间及历史记录。
- 同编号但凭证不同，或不同编号使用同一凭证：整个批次回滚，报错退出，不会覆盖线上数据。
- 清单格式、编号或哈希不合法：拒绝导入。

可安全重复导入同一份清单。发生冲突时先核对编号分配、目标数据库和设备原凭证，不要删除已有设备或整库覆盖来绕过冲突。若此前已登记过该编号，不能在另一台电脑重新生成一份新密钥来代替原密钥。

**不要把本机 SQLite 整库覆盖到线上，也不要在本机生成密钥后又到线上对同一编号执行一次普通登记。** 后者会生成另一份密钥，与杯垫不匹配。线上应导入本机导出的哈希。

## 5. 联网验收

导入完成后，给杯垫配置可联网的 2.4 GHz Wi-Fi。等待连接，再通过串口发送 `{"cmd":"status"}`，核对：

- `serverConfigured: true`、`wifiConnected: true`、`serverConnected: true`。
- `httpStatus: 200`，屏幕或状态中出现未过期的 8 位绑定码。
- `bound: false`，留给最终用户绑定账号。
- `calibrated: true`，断电重启后配置和标定保留。

`401` 时优先检查是否导入了正确的线上数据库、同一编号是否写入了错误密钥。`403` 时检查正式域名和反向代理 Host；TLS 失败检查证书及设备时钟。仅有 `ok: true` 或 Wi-Fi 已连接不算通过云端验收。

测试 Wi-Fi 会被保存。用户换网时在设备正常启动后长按 BOOT 三秒打开配网热点；不要依靠测试过的设备自动进入首次配网。

## 局域网联调与地址切换

服务器地址保存在杯垫 Flash 中，不必写死在固件，也不需要为每次切换重新生成密钥。配置入口为 USB 串口；用户热点页和云端命令不提供服务器地址修改。

1. 电脑和杯垫连接同一路由器，设备使用 2.4 GHz Wi-Fi。查看电脑当前 Wi-Fi 网卡的私网 IPv4，例如 `192.168.1.10`；Mac 可在“系统设置 → Wi-Fi → 当前网络详细信息 → TCP/IP”查看。
2. 在本机登记数据库与后端使用同一 `DB_PATH` 的前提下运行 `npm run dev`。API 使用 **3001** 端口，监听地址须为 `0.0.0.0` 或实际网卡 IP（开发默认 `0.0.0.0`）；已有 `.env` 若设为 `127.0.0.1`，仅本机能访问。允许本机防火墙接收该端口的局域网连接，路由器不要启用客户端隔离。
3. Arduino 串口选择 115200、新行，逐条发送并确认保存成功：

   ```json
   {"cmd":"server","url":"http://192.168.1.10:3001"}
   {"cmd":"reboot"}
   ```

4. 重启后发送 `{"cmd":"status"}`，确认 `cloudUrl`、`wifiConnected: true`、`serverConnected: true` 和 `httpStatus: 200`。只改地址保留身份、标定、空杯及本地记录；目标服务仍必须登记相同 ID 和 token 哈希。

HTTP 仅支持 `10.x.x.x`、`172.16.x.x`–`172.31.x.x`、`192.168.x.x` 私网 IPv4。不要填 `localhost`、`127.0.0.1`、`0.0.0.0`、网页开发端口 `5173` 或 `/api` 路径。局域网 HTTP 仅用于受控开发网络，设备凭证不加密传输；交付使用有效证书的 HTTPS。电脑 IP 改变后需重新设置地址，长期联调可在路由器中保留 DHCP 地址。

开发网页仍在电脑浏览器打开 `http://127.0.0.1:5173`，不要把设备 API 地址当成网页地址。开发时杯垫热点页的站点入口沿用 API 地址，不能替代电脑上的 Vite 网页。

上线时，先将登记清单导入线上数据库，再经 USB 切换地址并重启：

```json
{"cmd":"server","url":"https://你的正式域名"}
{"cmd":"reboot"}
```

切换地址不复制两套数据库的用户绑定、已上传历史或会话；本机与线上账号归属仍分别管理。设备中尚未上传的记录会在连接新目标后发送给新目标，联调数据请在交付前核对，不要把新服务器地址当作清理记录的操作。

## 凭证丢失与日常升级

只丢失命令输出、杯垫配置仍在时，设备可继续认证，也可从本机数据库导出哈希登记到线上；服务器哈希无法还原 token。需要重新写入设备时应使用受控备份中的原始配置。当前工具没有密钥重置功能，不会通过重复登记覆盖密钥，也不要求正常升级重烧身份。

保留设备编号、密钥、Flash 配置及线上数据库，正常升级只更新程序。工厂台账记录编号、固件版本、标定和联网验收结果即可，原始密钥另行受控保存。
