# 出厂标定与自动注册

0.7.0 起，新杯垫使用通用固件。用户登录、通过蓝牙填写 Wi-Fi 后，设备向服务端首次注册；服务端生成唯一六位编号、独立随机凭证并绑定当前账号，设备保存后确认完成。工厂无需逐台编号、导入清单或写入部署信任公钥。

## 部署准备

正式环境按 [部署说明](../deploy/README.md) 提供 HTTPS 网站与 API，设置 `APP_ORIGIN=https://实际域名`。没有配置旧版签名密钥也能使用自动注册。普通账号可以直接添加杯垫，不存在默认管理员账号，也不会自动把首位注册用户设为管理员。

只有需要维护服务器地址、查看设备列表时，才将明确的已注册账号提升为管理员：

```sh
DB_PATH=/实际持久目录/coaster.sqlite npm run admin -- --username 已注册账号
```

管理员的“配网服务器设置”支持生产 HTTPS origin；本地开发模式支持 RFC1918 私网 IPv4 HTTP。地址只含协议、主机和可选端口，不带路径、查询或凭据，最长 191 字节。网页自己的请求仍走同源 `/api`。

## 工厂标定与交付

1. 按 [固件说明](../firmware/README.md) 上传 0.7.0。保留 `partitions.csv`，选择 16 MB Flash、OPI PSRAM，关闭“擦除全部 Flash”。
2. 整机空载，通过 USB 执行 `tare`，放上已知质量执行 `calibrate`，再用其他重量复核。
3. 断电重启后确认 `calibrated: true`。工厂不替最终用户登记空杯。
4. 交付时用户用自己的账号完成 BLE 配网和绑定。测试中已绑定的设备，先由测试账号解绑。

称重标定依然是工厂职责；USB 不再是消费者首次绑定的必要步骤。已有设备升级保留配置、标定、历史队列和云端归属，不能通过重新配网解除原账号绑定。

## 用户使用与转绑

1. 在支持 Web Bluetooth 的 Chrome / Edge 登录网站。正式网站使用 HTTPS，本机开发也可用 localhost HTTP。
2. 新机通电，或在正常启动后长按 BOOT 三秒打开十分钟配网窗口。不要按住 BOOT 上电。
3. 网页点击“添加杯垫”，选择 Water-Coaster，按系统提示输入屏幕上的六位蓝牙配对码；无需先在系统蓝牙列表中配对。
4. 输入普通 2.4 GHz Wi-Fi 名称和密码。服务地址、短期票据自动下发。
5. 等待设备联网、自动注册、保存配置并完成服务端确认。仅蓝牙写入或 Wi-Fi 连上不代表成功。
6. 放上自己的空杯静置至少三秒，执行空杯设置并等待设备回执。

每账号同时绑定一台设备。同账号重配 Wi-Fi 保留设备编号、有效凭证、绑定批次和空杯；新主人绑定清空空杯、保留工厂标定。只有原账号可以解绑，解绑保留原账号历史。服务端按内部硬件标识识别同一开发板，普通配置重置不会绕过同一服务中的归属检查；这个标识不等同于防篡改硬件认证。

首次注册回执丢失或设备重启，会通过已保存的同一次操作查询结果。服务端只在设备提交持久化完成后标记成功；网页刷新不保存或重发 Wi-Fi 密码。原始设备凭证不进入网页。

## 局域网联调与地址切换

非生产模式下，`npm run dev` 的网页用 `http://localhost:5173` 或 `http://127.0.0.1:5173` 打开。设备 API 使用电脑的局域网地址，例如 `http://192.168.1.10:3001`，默认自动选择唯一可用的私网 IPv4。示例 `.env` 中网页的 localhost 地址不会作为设备地址下发。

电脑与杯垫需互通，后端监听 `0.0.0.0:3001`。多网卡或需要固定地址时，由管理员填写设备实际能访问的后端地址；也可将开发环境 `APP_ORIGIN` 指向该后端 origin。不要填网页端口 5173、localhost、127.0.0.1、0.0.0.0 或 `/api` 路径。

浏览器 Web Bluetooth 的限制与设备 HTTP 是两件事：局域网 IP 的 HTTP 网页不能调用蓝牙，Mac 本机 localhost 可以。开发 HTTP 不提供 TLS 加密；生产要求有效 HTTPS 证书并正常校验。

已有身份和保存地址的设备，BLE v2 重配要求同一 origin。服务器改域名或本地 IP 变化时，可在受控 USB 运维中只修改 `server url` 后重启；这不迁移账号与数据库，也不能解除已有归属。日常联调建议保持后端局域网地址固定。

```json
{"cmd":"server","url":"http://192.168.1.10:3001"}
{"cmd":"reboot"}
```

## 旧版兼容工具

0.6.x 的签名配网协议仍保留，管理员页面将逐台登记、导入与签名配置折叠。新流程不执行以下步骤：

- `npm run provisioning-key -- --out ./data/provisioning-private.pem` 生成旧部署签名私钥，配置 `PROVISION_SIGNING_KEY_FILE` / `PROVISION_DEPLOYMENT_ID`；不能替换已交付设备对应的密钥。
- `npm run provision -- --id coaster-000001` 为旧设备生成独立凭证，操作员将工具输出的 `server` 命令通过 USB 写入。
- 旧 `trust` 命令写入公开部署 UUID 与 P-256 公钥；私钥留在服务器。
- `npm run provision -- --export ./output/factory/batch-001.json --id coaster-000001` 导出仅含 `id/tokenHash/createdAt` 的清单，在管理员页面导入。相同身份幂等，冲突拒绝，不覆盖归属。

工具使用当前 `DB_PATH`；工厂本机库不会随代码自动部署。旧设备升级到 0.7.0 后，已在当前服务登记的身份先证明原凭证，再关联硬件标识，保留编号。尚未被当前服务登记的本机调试编号可在首次绑定时取得正式编号。数据库、历史和原设备凭证必须保留，不能把换库当成迁移。

## 故障与恢复

- 旧固件提示未建立信任：升级至 0.7.0 后使用自动注册流程。
- 提示设备属于其他账号：由原账号解绑，重配 Wi-Fi 无法替代解绑。
- Wi-Fi 密码错误或云端明确拒绝：恢复原配置后重新连接杯垫。
- 蓝牙断开、网页超时或 claim 回执丢失：继续查询同一次操作，避免覆盖恢复记录。
- 提示配置与设备不符：核对是否连接原杯垫、挑战是否已过期、已有服务地址是否变更。
- 升级前备份云端数据库；保留设备分区，不擦除 Flash。

协议细节见 [BLE 自动注册 v2](ble-provisioning-v2.md)。真实配对、Wi-Fi/BLE 共存、断电恢复和称重仍须真机验收。
