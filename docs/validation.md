## 2026-10-12 取放瞬态导致饮水漏记

用户反馈完全拿离杯垫、喝水再放回后，重量变化但没有记录。现有服务只读检查确认实物运行 0.4.4，已校准、已校时、Wi-Fi 与服务器连通，空杯约 272.9 g，待上传与待定时间均为 0，当日后端记录为空；未取得该次取放的逐点采样，因此不能断言现场唯一原因。

源码复现发现：单次读数低于空杯重量超过 1 g 就调用 `cancel_cycle`，杯子拿起或放下的部分受力读数会清掉饮水前基准。新增取杯过渡回归在修复前断言失败。0.4.5 将低于空杯的判断移到稳定窗口之后，短暂过渡保留基准，持续稳定的异常重量仍作废；取放要求、5 g 门槛、事件及校准格式保持。

`npm run test:firmware` 通过 C 称重 13 组及 HTTP／手机页／扫描 22 项。新增覆盖拿杯和放杯过渡、局部抬杯、原重放回、带过渡的补水及持续低于空杯；原有抖动、漂移、无效读数、采样中断和重启回归通过。使用实际称重模块与合成采样，不代表现场传感器验收。

未完整构建或烧录，设备仍需上传 0.4.5，保持“擦除全部 Flash”为 Disabled。上传后先让有水杯静置建立基准，再正常拿起喝水、放回并静置约两秒，核对真实事件生成与后端记录；已漏掉且未保存差值的动作无法自动补回。

## 2026-10-12 热点配网首页与短乱码修复

用户反馈打开 192.168.4.1 后只有一小段乱码或错误文字，并明确热点用于配网。源码检查发现：本机 esp32 3.3.11 启用 `CONFIG_LWIP_IPV6`，[ESP-IDF 5.5.5 HTTP 服务](https://raw.githubusercontent.com/espressif/esp-idf/v5.5.5/components/esp_http_server/src/httpd_main.c)使用 IPv6 双栈 socket，而原 `allowed` 仅识别 IPv4，导致 IPv4 映射地址的正常热点请求被拒绝。另外，原首页会拒绝来自聊天链接的跨站导航；[SDK 默认错误响应](https://raw.githubusercontent.com/espressif/esp-idf/v5.5.5/components/esp_http_server/src/httpd_txrx.c)将类型重置为不含 charset 的 `text/html`，中文短错误可能显示乱码。本次修正目标地址识别、允许静态首页导航，并显式发送 UTF-8 中文错误；API 同源限制保留。

0.4.1 首页直接填写 Wi-Fi 并保存重启，状态区区分热点已连接、等待重启、正在连接、连接失败和实际配网成功。新增只读 `wifiSsid`，避免旧网络连接被当作新配置成功；空杯与首次校准收进折叠区。热点密码仍为 `12345678`，已有后端、校准与事件存储格式不变。
