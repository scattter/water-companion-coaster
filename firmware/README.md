# ESP32-S3 Arduino 称重固件

目标硬件：微雪 **ESP32-S3-LCD-1.47B**、TAL220B 2 kg 四线传感器，以及用户已确认支持 3.3 V 供电、只有 VCC/GND/DT/SCK 接口的 HX711 成品板。开发板为 16 MB Flash、8 MB PSRAM，本版 HX711 统一使用 3.3 V 供电。使用 **Arduino IDE 2.x + esp32 by Espressif Systems 3.3.11**；本机已有该开发板包，所需底层组件随包提供，无需另外安装 HX711、ArduinoJson 或显示库。

直接用 Arduino IDE 打开 **[water_companion/water_companion.ino](water_companion/water_companion.ino)**。同一文件夹内的 `.c` / `.cpp` / `.h` 会一起参与编译，并可在 IDE 标签页编辑；GPIO 在 [board_config.h](water_companion/board_config.h) 中设置。请保留整个文件夹，尤其是同级 `partitions.csv`，不要只复制 `.ino`。Arduino 的“另存为”可能不复制 CSV，搬动工程时复制整个文件夹并核对分区文件；参见 [Arduino 工程规范](https://docs.arduino.cc/arduino-cli/sketch-specification/)。

当前实现 HX711 真实采样、校准与空杯登记、取放识别、NVS 事件队列、Wi-Fi、HTTP/HTTPS 上报、Type-C USB 串口命令和板载中文状态屏。固件版本 **0.4.5**，修复取放经过低重量读数时丢失饮水基准的问题；支持电脑 5173 网页直接通过 Wi-Fi 校准，热点首页可扫描并选择 Wi-Fi。此前的双栈访问和中文错误修复继续保留。按钮和蓝牙配网尚未接入。此版只做轻量检查，屏幕和联网仍需重新编译上传后用实物确认。

## 1. 接线

完整说明见 [接线与安装](../hardware/circuits/wiring.md)。

| HX711 | 微雪板丝印 |
|---|---|
| CLK / SCK | GP4（GPIO4） |
| DAT / DT / DOUT | GP2（GPIO2） |
| GND | GND |
| VCC | 3V3（OUT） |

这块 HX711 没有独立 VDD，不需补接该线；VCC 不沿用旧方案的 5 V 接法。传感器接 HX711 的 E+、E−、A+、A−，线序按器件资料确认。RATE 选择 **10 SPS**。先接称重链路，保持上盘自由受力。

GPIO 已按[微雪官方资料](https://docs.waveshare.net/ESP32-S3-LCD-1.47B/)核对。GPIO1 用于板载电池电压检测、未引出到排针，本版默认 **DOUT=2、SCK=4**。可以在 Arduino IDE 的 `board_config.h` 标签页查看；改线前断开电源。

## 2. Arduino IDE 设置与上传

开发板管理器选择 **esp32 by Espressif Systems 3.3.11**。打开上述 `.ino` 后，在“工具”菜单设置：

| 设置项 | 选择 |
|---|---|
| Board / 开发板 | **ESP32S3 Dev Module** |
| USB Mode | **Hardware CDC and JTAG** |
| USB CDC On Boot | **Enabled** |
| Upload Mode | **UART0 / Hardware CDC** |
| CPU Frequency | **240MHz (WiFi)** |
| Flash Mode | **QIO 80MHz** |
| Flash Size | **16MB (128Mb)** |
| PSRAM | **OPI PSRAM** |
| Partition Scheme | **16M Flash (3MB APP/9.9MB FATFS)**，实际由工程内 `partitions.csv` 覆盖 |
| Erase All Flash Before Sketch Upload | **Disabled** |
| Core Debug Level | **None** |
| Port / 端口 | 板子对应的 `/dev/cu.usbmodem...`，按实际枚举选择 |

这些菜单名称已与本机 3.3.11 的 `boards.txt` 核对。USB 模式或 CDC 开关不符时，工程会在编译时报出具体设置提示。Arduino 的 `Serial` 使用板载 Type-C USB Serial/JTAG，命令无需接 TX/RX；未打开电脑串口时也会继续启动与采样。

点击“验证”，通过后点击“上传”。上传后打开“串口监视器”，选择 **115200** 和 **新行（New Line）**；重启后若端口变化，重新选择端口。首次看不到启动信息时可按 RESET，或直接发送 `{"cmd":"status"}`，再发送 `{"cmd":"watch","enabled":true}` 查看原始读数。

烧录不成功时确认 Type-C 线可传数据；必要时按住 BOOT、按一下 RESET，再松开 BOOT，重新选择端口后上传。芯片的 USB 下载要求参见[乐鑫 Arduino USB 说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/cdc_dfu_flash.html)。

工程的分区表为 Arduino 固定写入的 `0xe000–0xffff` 启动数据预留空间，配置另存于 `settings`，离线事件使用独立的 2 MB `events`；正常 Arduino 串口上传不写这两个分区。不要开启“擦除全部 Flash”。缺少正确分区时固件会报告初始化失败，不能省略 CSV 后使用默认分区。

从 Arduino 0.3.x 或较早的 0.4.x 更新时分区和保存格式不变，正常上传保留联网配置、校准和事件。原 ESP-IDF 的校准和联网配置不自动迁移，首次改用 Arduino 后执行下方配置与校准。如果已在旧固件中保存事件，应先使用旧固件上传或导出；发现旧队列却没有配套启动编号时，新固件会停止初始化、保留数据，避免把旧记录归到错误的时间或设备。

### 板载屏幕

上电进入应用后显示“水伴杯垫 0.4.5”，每 500 ms 检查一次状态，只重绘变化的文字行。使用 Arduino 自带 SPI 驱动 ST7789，分辨率 172×320、X 偏移 34；GPIO 为 MOSI=45、SCLK=40、CS=42、DC=41、RST=39、背光=46。

| 区域 | 显示内容 |
|---|---|
| 手机直连 | Water- 热点名、固定密码 12345678 及 192.168.4.1；启动失败显示错误提示 |
| Wi-Fi | 未配置、正在连接、已连接、找不到网络或检查密码；更详细的原因码见手机页 |
| 服务器 | 未配置、等待 Wi-Fi、等待校时、心跳确认后已连接、连接失败或凭证错误；HTTP 状态见手机页 |
| 称重 | HX711 未就绪、等待校准、实时克数、空杯登记和稳定状态 |
| 底部 | 待上传条数、待定时间条数；修改联网设置后提示重启；保存失败优先提示勿断电 |

Wi-Fi 连上路由器不等于后端连接成功。服务器状态仅在心跳返回 `200` 且 `ok: true` 后显示已连接；请求失败、断网或超过 15 秒未确认会取消成功状态。LCD 在称重和存储初始化前启动，因此应用初始化失败时可显示错误码；如果仍卡在引导程序的分区校验阶段，应用无法点亮屏幕，先按上表核对 **Flash Size=16MB**。

中文固定文案使用已随工程附带的字形子集，无需安装字体。新增屏幕文案后，按 [字体说明](water_companion/display-font-license.txt)重新生成 `display_font.h`。

## 3. 连接热点配网

上电立即开启 **Water-XXXXXX** 热点，不等待路由器连接。手机或 Mac 连接屏幕显示的热点，输入固定密码 **12345678**，选择保持连接无互联网的网络，浏览器打开 **http://192.168.4.1**。配网页内置于固件，不依赖电脑服务、外部网页资源、蓝牙或互联网。

1. 首页自动扫描附近 **2.4 GHz Wi-Fi**，在列表中选择家里或办公室的网络，输入密码，可用“显示密码／隐藏密码”核对，再点击“保存并连接 Wi-Fi”；配网不要求先校准称重。列表按信号强弱排列，同名网络只显示一次。
2. 保存成功后以可关闭浮窗提示，杯垫自动重启，热点暂时断开。重新连接 Water- 热点并保持页面打开，页面会继续检查联网结果。操作反馈悬浮显示，不挤占页面内容。
3. 只有设备实际连接所填网络，页首绿色卡片才显示“已经成功连接 XXX”与局域网地址；再次访问仍依据最新设备状态显示。找不到网络、密码错误等会显示原因，可修改后重新保存；只收到保存或重启确认不算成功。
4. 成功后将手机或 Mac 切回家里 Wi-Fi。杯垫下次上电自动连接；热点保留，便于以后更改网络与空杯设置。

未找到网络可点“重新扫描”；隐藏网络选择“手动输入（隐藏网络）”。若杯垫正尝试连接已有网络，扫描会提示稍后重试，不会主动断开已有连接。扫描失败不清空已选网络和密码。

展开下方“空杯与称重设置”，可查看实时重量、更新空杯、完成一次性的重量校准，以及查看本次开机内最近一次差值、记录保存状态和待上传条数。完整已上传历史保留在电脑网页。热点使用 WPA2，密码在 `network.h` 的 `CONTROL_PASSWORD` 中固定为 `12345678`；旧随机密码的存储键留存但不使用，无需擦除 Flash。状态接口不返回热点密码、路由器密码或设备凭证。

旧版只出现一小段乱码时，重新上传 0.4.5：HTTP 双栈连接中的 IPv4 映射地址现已正确识别，中文错误响应显式使用 UTF-8。Mac 可用 Safari 或 Chrome 打开同一页面；本版仍需在实机确认连接和重启流程。

手机页面会在设备未校时时使用手机日期设置时钟，不覆盖已建立的时钟。同一次启动内未校时的已保存记录随后会回填时间，不需要先配置上传服务器；跨断电的未知时间记录仍不能自动恢复。每次冷启动后建议打开一次手机页再使用，手机系统时间需准确。

如需电脑历史统计，可在电脑网页“设置 → USB 备用设置”中写入后端地址与凭证；热点配网沿用已有后端配置。固件使用 AP+STA，未配置时 STA 只用于扫描，不主动连接路由器；已有配置时自动连接，路由器断线不关闭配网页。Wi-Fi 连上不代表后端已连接，电脑后端仍需运行。ESP32-S3 支持此模式，参见[乐鑫 Wi-Fi 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/network/esp_wifi.html)。

以下串口操作保留供电脑配网与排查使用；手动使用串口监视器前，先在网页断开 USB。

在 Arduino 串口监视器发送单行 JSON，以换行结束。固件不回显输入或凭证；终端如自行保存会话日志，请妥善保管。

先按 [电脑端启动说明](../README.md#启动电脑端)配置 `.env`，运行 `npm run dev`。电脑端与设备使用相同的 `DEVICE_ID`、`DEVICE_TOKEN`。电脑和杯垫处于可互通的同一局域网；Mac 的“系统设置 → Wi-Fi → 当前网络详细信息 → TCP/IP”可查看电脑 IPv4 地址，以下用 `192.168.1.10` 举例，需替换为实际值。允许电脑防火墙的 TCP 3001 入站；网页在电脑打开 `http://127.0.0.1:5173`。

依次发送，替换示例值：

```json
{"cmd":"wifi","ssid":"你的2.4G网络","password":"你的Wi-Fi密码"}
{"cmd":"server","url":"http://192.168.1.10:3001","id":"coaster-01","token":"填入与.env相同的设备凭证"}
{"cmd":"reboot"}
```

前两条分别返回 `ok: true` 后再发送下一条。屏幕提示“联网设置已保存／请重启以生效”。重启后分别确认 Wi-Fi 和服务器显示已连接；详细 IP 与 HTTP 状态可在手机页查看。也可发送 `{"cmd":"status"}` 查看 `wifiConnected`、`serverConnected`、`ip`、`wifiReason`、`httpStatus` 和 `restartRequired`；不返回密码或凭证。

若只需先确认 Wi-Fi，可先发送 `wifi` 和 `reboot`；Wi-Fi 可独立连接，此时服务器区域显示未配置。随后写入 `server` 并再次重启。联网配置保存后，下次上电自动连接，USB 不需要一直连着电脑；要实时上传，电脑后端仍需运行。

- URL 只填协议、主机、端口，不带路径。HTTP 只接受 10.x、172.16–31.x 或 192.168.x 的局域网 IPv4 地址；HTTPS 接受域名并验证系统证书包，不跳过证书校验、不自动跟随重定向。
- Wi-Fi 支持普通密码网络；SSID 最长 32 字节，密码为 8–63 字节，开放网络填空字符串。企业认证或需要网页认证的网络未实现。
- 联网配置写入后需重启；等待重启期间暂停新事件识别。校准命令不需要重启。
- Wi-Fi 首次立即连接，掉线后每三十秒尝试重连，上传失败保留事件并退避重试，采样任务独立运行。
- 有待处理事件时不能修改设备编号。电脑 IP 改变时可更新服务器地址，保留相同编号和凭证后重启。
- 局域网心跳可使用电脑返回的时间进行初始校时。HTTPS 首次连接需 SNTP 或手机校时成功，SNTP 默认使用 `pool.ntp.org`；时钟未建立时不关闭 TLS 校验。

## 4. 日常更新空杯，首次校准一次

每次移动物体后静置至少三秒，确认结构与读数稳定。

0.4.4 起支持直接在电脑 **5173 网页**通过 Wi-Fi 校准。杯垫与电脑保持同一可互通网络，并已配置后端、成功上报后，点击首页“开始校准”，或右上角“设置”，依次执行空载归零、重量校准、更新空杯，全程不切换热点、不选择串口。0.4.3 需重新上传本版，保持“擦除全部 Flash”为 Disabled；配置和事件格式未改变。已完成校准的 0.4.4 设备升级 0.4.5 时不需重复校准。

日常只需放空杯并点击“更新空杯重量”（`cup`），不重新归零。手机热点页和电脑 USB 入口继续可用；热点页先展开“空杯与称重设置”，首次尚未校准时，再展开其中的“首次设置”。所有入口复用 `tare`、`calibrate`、`cup`，设备返回成功才显示保存完成；不稳定或传感器未就绪时显示失败原因。

1. 装好承重上盘，移走杯子和砝码，发送：
   `{"cmd":"tare"}`
2. 放 **500 g 已知质量的物品**（或另一台秤称准的空杯，参数改为实际克数，支持 50–2000 g），静置后发送：
   `{"cmd":"calibrate","grams":500}`
3. 移走砝码，用其他已知质量复核读数；再放空杯，静置后发送：
   `{"cmd":"cup"}`
4. 查看状态，或开启每秒一次的串口读数：

```json
{"cmd":"status"}
{"cmd":"watch","enabled":true}
{"cmd":"watch","enabled":false}
```

HX711 输出原始数值；重量差仍需除以校准得到的 `counts_per_gram` 才是克数，空杯重量不能替代这个换算比例。因此首次校准不能省略，但不必每次使用都做。

`tare` 会使原重量校准和空杯登记失效；重新校准后必须再次登记空杯。更换杯子通常只需重新执行 `cup`。固件不会在每次启动时归零，重启时已有杯子只建立基准，不生成饮水记录。

校准需要连续有效原始采样。零点初次校准要求 20 个原始读数跨度不超过 1000 counts；已校准后按约 1 g 的跨度检查。砝码与空杯也要求约 1 g 内稳定。若总是失败，先检查结构、接线和噪声；不要把失败当作校准成功。

当前取放规则：约 10 Hz 采样、至少连续 0.5 秒离杯、放回后约两秒稳定、波动不超过 1 g。变化至少 5 g 才记录；上升记补水、下降记估算饮水，无完整取放的慢漂移不计数。参数和误差目标仍需真机校验。

取放时杯子部分受力，低于空杯重量的短暂读数不清除基准；稳定后仍低于空杯超过 1 g 才作废本次取放。超量程、无效读数和采样中断仍立即作废。0.4.5 之前可能因这一过渡过程漏记；未生成事件的历史动作没有可供补传的完整差值，不能自动补回。

## 5. 事件保存与故障

- 事件先写独立 NVS 分区，服务器明确确认该 UUID 后才删除。重传使用原 UUID 和原内容。
- 最多保存 4096 条事件。写入失败或缓存已满时保留当前待写事件于 RAM、暂停新事件识别，并在串口和可用的心跳中报告；恢复上传腾出空间后再保存。此时不要断电，RAM 中的那一条尚无断电保障。
- 数据损坏或 NVS 初始化失败会报告错误并停止，固件不会自动擦除数据。
- 尚未校时的事件保存启动编号和相对时间；同一次启动联网后回填发生时间，再上传。
- **断电前一直未校时的记录无法自动恢复绝对时间**，保留在 Flash，计入 `timePendingCount`，不进入每日统计，也不会阻塞其他已知时间事件。通过 `{"cmd":"pending-time"}` 导出这类记录供人工处理；该命令不删除或擅自定时。
- 设备继续记录不依赖网页，但当前电脑后端必须运行才能实时上传；后端停机时进入本地缓存。

## 6. 轻量检查和上板验收

项目根目录执行 `npm run test:firmware`，用本机 C 编译器测试 Arduino 工程实际采用的 `water_companion/weighing.c`，覆盖取放、补水、漂移、异常、采样中断、更新空杯和重启基准；同一命令还测试实际配网页脚本、Wi-Fi 扫描函数、HTTP 校验与错误响应函数。覆盖网络选择、重扫、隐藏网络、扫描忙／超时后的资源释放，以及双栈地址、聊天链接、同源限制和中文编码。驱动、HTTP 与 DOM 使用替身，不监听端口、不编译完整固件，也不证明浏览器兼容性、接线、精度或热点联网正常。

上板后按 [验收清单](../docs/validation.md)逐项记录。USB 烧录、真实称重、Wi-Fi、校准重启保持、确认丢失重传及 Flash 断电恢复均需实际执行。
