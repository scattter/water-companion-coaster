# ESP32-S3 Arduino 称重固件

目标硬件：微雪 **ESP32-S3-LCD-1.47B**、TAL220B 2 kg 四线传感器，以及用户已确认支持 3.3 V 供电、只有 VCC/GND/DT/SCK 接口的 HX711 成品板。开发板为 16 MB Flash、8 MB PSRAM，本版 HX711 统一使用 3.3 V 供电。使用 **Arduino IDE 2.x + esp32 by Espressif Systems 3.3.11**；本机已有该开发板包，所需底层组件随包提供，无需另外安装 HX711、ArduinoJson 或显示库。

直接用 Arduino IDE 打开 **[water_companion/water_companion.ino](water_companion/water_companion.ino)**。同一文件夹内的 `.c` / `.cpp` / `.h` 会一起参与编译，并可在 IDE 标签页编辑；GPIO 在 [board_config.h](water_companion/board_config.h) 中设置。请保留整个文件夹，尤其是同级 `partitions.csv`，不要只复制 `.ino`。Arduino 的“另存为”可能不复制 CSV，搬动工程时复制整个文件夹并核对分区文件；参见 [Arduino 工程规范](https://docs.arduino.cc/arduino-cli/sketch-specification/)。

当前固件源码 **0.7.3** 实现 HX711 采样、出厂标定、空杯登记、离线事件保存、BLE 自动注册配网、热点兼容配网、云端命令与绑定后的日常信息页，并保留 0.6.1 启动内存修复。蓝牙配对后，网页可读取杯垫实际扫描到的 2.4 GHz Wi-Fi，选择网络并填写密码。用户首次配网后由服务端生成编号和独立凭证并写入设备，不需要预登记或 USB 写信任配置。BLE 使用开发板包自带的 NimBLE 和 mbedTLS；GPIO0 的 BOOT 键用于正常启动后长按配网。本轮进行了服务端类型检查、相关回归和固件主机测试，未完整构建、启动服务、部署、烧录或进行真机验收。

## 1. 接线

完整说明见 [接线与安装](../hardware/circuits/wiring.md)。

| HX711 | 微雪板丝印 |
|---|---|
| CLK / SCK | GP4（GPIO4） |
| DAT / DT / DOUT | GP2（GPIO2） |
| GND | GND |
| VCC | 3V3（OUT） |

这块 HX711 没有独立 VDD，不需补接该线；VCC 不沿用旧方案的 5 V 接法。传感器接 HX711 的 E+、E−、A+、A−，线序按器件资料确认。RATE 选择 **10 SPS**。先接称重链路，保持上盘自由受力。

GPIO 已按[微雪官方资料](https://docs.waveshare.net/ESP32-S3-LCD-1.47B/)核对。GPIO1 用于板载电池电压检测、未引出到排针，本版默认 **DOUT=2、SCK=4**。可以在 Arduino IDE 的 `board_config.h` 标签页查看；改线前断开电源。

## 2. Arduino IDE 设置与上传

开发板管理器选择 **esp32 by Espressif Systems 3.3.11**。打开上述 `.ino` 后，在“工具”菜单设置：

| 设置项 | 选择 |
|---|---|
| Board / 开发板 | **ESP32S3 Dev Module** |
| USB Mode | **Hardware CDC and JTAG** |
| USB CDC On Boot | **Enabled** |
| Upload Mode | **UART0 / Hardware CDC** |
| CPU Frequency | **240MHz (WiFi)** |
| Flash Mode | **QIO 80MHz** |
| Flash Size | **16MB (128Mb)** |
| PSRAM | **OPI PSRAM** |
| Partition Scheme | **16M Flash (3MB APP/9.9MB FATFS)**，实际由工程内 `partitions.csv` 覆盖 |
| Erase All Flash Before Sketch Upload | **Disabled** |
| Core Debug Level | **None** |
| Port / 端口 | 板子对应的 `/dev/cu.usbmodem...`，按实际枚举选择 |

这些菜单名称已与本机 3.3.11 的 `boards.txt` 核对。USB 模式或 CDC 开关不符时，工程会在编译时报出具体设置提示。Arduino 的 `Serial` 使用板载 Type-C USB Serial/JTAG，命令无需接 TX/RX；未打开电脑串口时也会继续启动与采样。

点击“验证”，通过后点击“上传”。上传后打开“串口监视器”，选择 **115200** 和 **新行（New Line）**；重启后若端口变化，重新选择端口。首次看不到启动信息时可按 RESET，或直接发送 `{"cmd":"status"}`，再发送 `{"cmd":"watch","enabled":true}` 查看原始读数。

烧录不成功时确认 Type-C 线可传数据；必要时按住 BOOT、按一下 RESET，再松开 BOOT，重新选择端口后上传。芯片的 USB 下载要求参见[乐鑫 Arduino USB 说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/cdc_dfu_flash.html)。

工程的分区表为 Arduino 固定写入的 `0xe000–0xffff` 启动数据预留空间，配置另存于 `settings`，离线事件使用独立的 2 MB `events`；正常 Arduino 串口上传不写这两个分区。不要开启“擦除全部 Flash”。缺少正确分区时固件会报告初始化失败，不能省略 CSV 后使用默认分区。

从 Arduino 0.3.x 或较早的 0.4.x 更新时分区和保存格式不变，正常上传保留联网配置、校准和事件。原 ESP-IDF 的校准和联网配置不自动迁移，首次改用 Arduino 后执行下方配置与校准。如果已在旧固件中保存事件，应先使用旧固件上传或导出；发现旧队列却没有配套启动编号时，新固件会停止初始化、保留数据，避免把旧记录归到错误的时间或设备。

### 0.6.1 启动内存修复

0.6.0 在蓝牙和网络启动后动态申请 8 KB 串口任务栈，内部堆不足会触发 `ESP_ERROR_CHECK` 并循环重启。0.6.1 将串口/采样任务的完整 8192/4096 字节栈及控制块预留在内部 RAM，不缩小栈；串口先创建，等待初始化结果后再处理命令。

4096 条事件的 32 KiB 可重建索引改在 PSRAM 分配，事件数据、编号、凭证、标定和分区布局不变。**PSRAM 必须选择 OPI PSRAM**；配置错误在编译时拒绝，实际 PSRAM 未初始化或分配失败时返回明确错误，不回退占用内部堆，也不擦除 Flash。网络初始化失败会传回屏幕；串口仍接受 `status`/`diagnostics`，其他存储操作在失败状态拒绝，避免读取未初始化的数据。

启动日志包含 `boot[阶段] internal free/largest/min; PSRAM total/free/largest`。串口发送 `{"cmd":"diagnostics"}` 返回固件版本、启动阶段、错误和内存值，不含任何凭证。烧录当前版本后应看到 **0.7.3**（包含此修复）、最终 `boot[ready]` 与启动成功消息；若仍失败，保留这段日志判断实际硬件内存，而非重复擦除或烧录旧固件。

热点 HTTP 页面仅在热点配网窗口运行，日常 STA 模式不启动，窗口结束释放服务栈；长按 BOOT 三秒仍可再次开启。首次无 Wi-Fi 的设备保留原热点兼容入口。

### 板载屏幕

已持久保存账号绑定的杯垫默认显示 172 × 320 日常页，重启后仍按此规则选择页面。顶部为“水伴”和同步状态；今日饮水为蓝色大数字，`ml` 紧跟数字；中间显示绿色杯中余水（保留“约”）和暖橙色饮水次数；下方显示当天最近一次饮水量、距今时间和设备提示。水量仅在显示时四舍五入到整数，长数字自动缩小，原始数据精度不变。

杯中余水来自稳定重量减去已登记空杯重量。无杯、未设置空杯、称重未稳定及传感器异常分别显示对应提示；保存失败等异常优先于“杯垫工作正常”。只有统计有效、Wi-Fi 和云端正常且没有待同步记录时显示“已同步”。短按 BOOT 亮屏，15 秒后熄屏；长按 3 秒仍进入配网，配网期间显示原配网信息，完成后返回日常页。

日常页使用按实际字号生成的无衬线中文和窄体数字，字模保存 4 位灰度覆盖率，绘制时混合为 RGB565 抗锯齿边缘；数字、前缀和单位共用基线，长数字选择较小的字号。字模保存在只读数据中，位图约 98 KiB，仍复用 20 行 SPI 绘制缓冲，无需整屏帧缓冲或运行时字体库。生成脚本为 `scripts/generate-daily-font.py`，字体来源、许可证及生成方法见 [日常页字体说明](water_companion/daily-font-license.txt)。

未绑定及配网页面继续显示热点凭据、Wi-Fi 与云服务连接状态、短时账号绑定码、重量及记录队列。绑定后或码过期后不再显示旧码。该页面保留原点阵字体；修改文案后按 `display-font-license.txt` 重新生成子集。日常页文案变更时还需重新生成抗锯齿子集。

#### 心跳摘要与发布

`POST /api/device/heartbeat` 响应新增可选 `dailySummary`；未绑定或请求绑定批次不匹配时为 `null`。对象字段为 `date`（服务端配置时区的 `YYYY-MM-DD`）、`expiresAtMs`（该时区次日零点）、`drinkMl`、`drinkCount` 和 `lastDrink`；最近一笔为 `{ amountMl, occurredAtMs }`，当天没有有效饮水时为 `null`。账号、日期、撤销和补传去重口径与 App 一致，补水不计入，不新增数据库表。

固件只接受当前连接且绑定批次匹配的摘要，保存在内存中。断网保留当天最近同步值，待上传记录不在本地重复累加；上传成功后等待下一次心跳再标记已同步。跨日、解绑、换绑或重配后旧摘要失效，重启后重新同步。旧服务端未返回摘要时显示“统计暂不可用”，称重及配网继续工作。

发布顺序为**服务端先、固件后**。真机验收需确认绑定及重启后的页面、LCD 字体与颜色、长数字和单位、空杯/取杯/传感器异常提示、断网补传和跨日、解绑换绑、配网页面切换，以及短按亮屏/15 秒熄屏/长按配网。主机测试与像素预览不代表真机或生产验收。

## 3. 用户配网、绑定及更换 Wi-Fi

### BLE 自动注册配网（0.7.0）

1. 没有 Wi-Fi 或尚无绑定的新机上电开放十分钟 BLE 窗口；之后正常运行时长按 BOOT 三秒重新开放。设备名为 **Water-Coaster**。无需 USB 写入 ID、token、部署 UUID 或信任公钥。
2. 登录支持 Web Bluetooth 的网站，在网页选择设备，按系统提示输入屏幕上的随机六位 BLE 配对码（保留前导零）。采用 Secure Connections + MITM、16 字节加密密钥，不保存跨主人的 bond。
3. 网页读取内部硬件标识和挑战，为当前账号领取五分钟票据，再将 Wi-Fi、服务地址、票据发送给设备。挑战在同一次连接中固定且只能接收一次；过期后重新连接。
4. 设备核对硬件、挑战、窗口和地址，先写恢复日志再连接候选网络。第一次联网注册由服务端分配编号和凭证，设备保存 Wi-Fi、地址、身份和 bindingId，再提交完成。同主人重配保留编号、有效凭证、批次与空杯；换主人只清空空杯，工厂标定保留。
5. Wi-Fi 45 秒失败或云端明确拒绝后回滚。claim 回执不确定或断电重启时，只查询同一次操作，不重复认领。服务端已生成的新凭证可用原票据恢复，设备保存前网页不显示成功。Flash 写入或清理失败持续恢复，请保持供电。
6. 正式地址使用 HTTPS 并验证证书；本地开发可用私网 IPv4 HTTP，例如 `http://192.168.1.10:3001`。Mac 网页使用 `http://localhost:5173`，设备不能访问这个 localhost。已有身份和服务地址的设备，BLE 只接受原 origin；改地址使用受控运维入口。

服务 `7d2a0001-7b9c-4e6a-9f21-531bd67a0c10` 下，info/config/status 分别为 `0002/0003/0004`（其余 UUID 字段相同）。分片、认证加密、十秒收包超时、4096 字节上限沿用 v1。状态 READ 返回完整 JSON，NOTIFY 只作变更通知。BLE 不接收用户指定的正式 ID、长期 token 或 trust；正式身份仅从设备注册接口取得。

新配置使用 `protocolVersion:2`；旧 v1 签名解析与恢复仍保留，见 [v1 协议](../docs/ble-provisioning-v1.md)。详情见 [自动注册 v2](../docs/ble-provisioning-v2.md)。Core Debug Level 必须 **None**，避免底层库输出配对码或配置分片；固件不记录 Wi-Fi 密码、ticket 或原始 token。

### 原热点入口（保留）

此入口需要设备已有服务器地址和认证身份；全新设备先使用 BLE 自动注册。

1. 首次上电没有 Wi-Fi 配置时自动开放 **Water-XXXXXX** 热点。热点密码为每台独立生成并保存的 12 位密码，见屏幕；不是固定的 12345678。连接热点后选择保持无互联网连接，浏览器打开 **http://192.168.4.1**。
2. 选择家里或办公室的 **2.4 GHz Wi-Fi**，输入密码并保存。列表支持扫描、重试和隐藏网络手动输入。杯垫重启验证新网络，手机重新连接热点查看结果。
3. 新 Wi-Fi 先暂存在独立设置键，实际取得网络地址后才保存为主配置。45 秒仍未成功或配置保存失败时回到原网络，页面提示重试。更换网络不会改设备身份、账号归属、出厂标定、空杯或事件记录。候选配置清理失败时显示保存错误并每 5 秒重试，不会擦除配置或事件。
4. Wi-Fi 连接与云服务连接分别确认。云端心跳成功且设备未绑定时自动申请一次 **8 位数字绑定码**，有效期 5 分钟；用户也可在热点页主动刷新。屏幕和热点页显示绑定码，热点页显示正式网站入口。
5. 记下码，手机切回正常网络，再打开网站注册或登录并输入绑定码。不要依赖配网页自动跳转：热点本身没有互联网。绑定成功后登录网站查看最近状态和历史记录。
6. 放上日常使用的空杯，静置至少 3 秒，在网站点击空杯设置；也可在热点页设置。只有设备实际执行并回报成功，网站才显示完成。用户无需砝码。

后续更换路由器、密码或使用地点：**杯垫启动完成后长按 BOOT 3 秒**，开放 10 分钟配网窗口，再按上述方式操作。不要按住 BOOT 上电，那会进入烧录模式；窗口结束可再次长按。日常断网只自动重连，不自动长期开放热点。BOOT/Key1 为 GPIO0，按[微雪 1.47B 官方原理图](https://files.waveshare.com/wiki/ESP32-S3-LCD-1.47B/ESP32-S3-LCD-1.47B_schematic_diagram.pdf)核对。

热点页面仅提供 Wi-Fi、空杯、绑定码及状态，不提供重量标定或服务器凭证设置；不开放旧局域网控制接口。HTTP 仅接受发往热点地址的同源请求，支持 IPv4 和 IPv4 映射双栈地址。路由器密码、设备密钥和热点密码不会通过状态 JSON 返回。

手机页仅在时钟未建立时提交手机日期，之后不覆盖时钟。HTTPS 需先由 SNTP 或手机校时，证书校验不会因未校时而跳过。普通 Wi-Fi 密码网络和开放网络可用；企业认证和需网页认证的网络未实现。

## 4. 出厂重量标定与兼容运维

0.7.0 通用固件无需工厂分配设备编号和凭证。首次绑定时由服务端生成 `coaster-000001`–`coaster-999999` 范围内的唯一编号及 32 字节随机凭证，设备持久保存；已登记设备升级保留原身份。串口仍可执行重量标定与只读 `factory-info`，但这些不进入用户绑定流程。

旧 `server` / `trust` 命令保留受控运维；网页手工登记、清单导入与 `provision` CLI 已移除，见 [出厂与运维说明](../docs/factory-provisioning.md)。`server` 可单独更新 `url`，或成对更新 `id/token`；省略配置保持不变。保存后重启，存在待上传事件时禁止通过 USB 改设备编号。`factory-info` 只返回身份、凭证指纹、地址和公开信任信息，不返回原始 token。

已有设备需要切换局域网后端地址时，可通过 USB 发送：

```json
{"cmd":"server","url":"http://192.168.1.10:3001"}
{"cmd":"reboot"}
```

替换为实际后端 origin，不填 localhost、网页端口 5173 或 `/api` 路径。服务目标需保留原数据库与归属；改地址不会迁移数据或解绑。新机使用 BLE 时地址自动下发，无需此 USB 步骤。

整机装配完成后操作，每次移放物品后静置至少三秒：

1. 移走杯子与已知质量物品，保留承重盘，执行 `{"cmd":"tare"}` 保存零点。
2. 放上 **500 g 已知质量物品**，执行 `{"cmd":"calibrate","grams":500}`。支持 50–2000 g，参数必须是实际已知质量。
3. 移走物品，以其他已知质量复核读数；用 `{"cmd":"status"}` 或 `{"cmd":"watch","enabled":true}` 查看。交付前确认 `calibrated: true`，再关闭 watch。
4. 空杯由最终用户首次使用时设置，不要求工厂预先登记。

重量换算为 `(原始读数 − 零点) / counts_per_gram`。出厂标定提供换算比例，未知质量的空杯无法代替。原始采样需要连续稳定；标定与空杯要求约 1 g 内稳定。精度仍需实物检验。

`tare` 现在只修正零点，保留原比例和空杯设置；仅工厂串口可调用。重新执行 `calibrate` 会清除空杯设置，用户之后重新放空杯登记。固件不会每次开机自动归零，避免将杯子重量当零点。工厂更换传感器后需重新完成标定。

## 5. 云端命令、记录保存与升级

设备活动时每 5 秒、静置 30 秒后每 30 秒主动发送认证心跳，接收云端的 `cup` 命令；不需要云服务器访问用户局域网。仅执行未过期、格式有效的空杯命令，拒绝重量标定等命令。执行前持久保存命令身份，执行后持久保存结果，结果随心跳重发直到确认；重启和重复投递不会重复设置空杯。若执行过程中断电，回报“设置可能已保存，请检查后重试”，不会擅自再次称量。

账号归属由云端保存；重新配网或普通固件更新不会解绑。设备事件仍先写独立 NVS `events` 分区，云端确认该 UUID 后才删除，离线上限 4096 条。缓存满或写入失败会保留尚未写入的 RAM 事件并暂停识别，此时不要断电。数据损坏时停止并报告，不自动擦除。

本版保持原 `config` 版本 1 和分区布局；新事件版本 2 在生成时冻结 `bindingId`，补传时不会换成当前主人。读取原版本 1 事件时保留原 blob，不整队重写；上传明确携带 `bindingId:null`，由云端隔离，不能归给新主人。同次启动的时间补写保持原事件版本/尺寸。当前绑定、旧版部署信任根、配网恢复日志分别保存在 `binding_v1`、`trust_v1`、`provision_v1`。0.7.0 按 blob 大小兼容读取旧 v1 日志；v2 日志追加硬件标识、服务端分配身份，主配置结构和分区不变。

心跳、事件和命令回执带批次；只执行 bindingId 与当前持久批次一致的云命令。旧 pending 命令保留并以 null 批次回报后确认，不重复执行。日常心跳发现主人变化时，先清除用户空杯基准再保存新 bindingId；保留工厂标定。相同 bindingId 的 Wi-Fi 重配保留空杯。已结束批次事件仍按原批次补传，不影响新主人。按原分区表升级并关闭“擦除全部 Flash”，保留旧身份、标定和队列。

冷启动离线时保存事件相对时间；同一次启动完成校时后回填绝对时间。断电前从未校时的记录不能恢复真实日期，保留在 Flash 的待定时间队列，不进入每日统计，也不阻塞已知时间事件。工厂可用 `{"cmd":"pending-time"}` 导出供人工处理。

称重以约 10 Hz 采样，连续约两秒、波动不超过 1 g 才确认稳定，至少 5 g 差值才记录。饮水需连续 0.5 秒离杯后放回；补水也支持杯子留在杯垫上直接加水，稳定增重后记录一次。空杯设置成功后使用刚确认的杯重作为基准，可以直接加水；普通重启或采样中断后仍需重新建立稳定基准，不把恢复时已有的水计作新补水。离线继续识别与保存，云服务恢复后上传。

倒水也会计入取放后的重量减少，不能识别实际喝下的量。持续手压、添加杯盖等稳定增重无法只凭重量与加水区分，可能记作补水；误记可在网页撤销。未达到稳定条件的短暂手压和每次小于 5 g 的缓慢漂移不生成记录，缓慢滴水也可能被忽略。

### 0.7.2 省电策略

- 本地保持约 10 Hz 采样；相对上次活动的重量累计变化至少 5 g 才刷新联网活动时间、加快心跳，不会点亮屏幕。
- 屏幕上电默认熄灭，仅按侧边 BOOT 键点亮，15 秒后自动熄屏并暂停绘制；再次按下重新计时。取放、加水、配网和故障都不自动点亮或延长亮屏，熄屏时仍继续称重与上传。长按三秒仍进入配网，需要查看配对码或错误时再短按亮屏。
- 上电向 GPIO38 的板载 RGB 灯发送全黑，运行期间不点亮。充电指示灯由充电芯片直接驱动，不能通过固件关闭，见[开发板原理图](https://files.waveshare.com/wiki/ESP32-S3-LCD-1.47B/ESP32-S3-LCD-1.47B_schematic_diagram.pdf)。
- 空闲心跳 30 秒，活动及待确认命令回执 5 秒；事件上传独立运行，不等待空闲心跳。心跳失败退避为 5、10、20、40、60 秒，重新连接 Wi-Fi 后立即重新确认。
- HTTP 客户端复用同源连接，不启用额外 TCP keepalive 探测；断网、换 origin 或失败后清理连接。每次请求重置正文和认证头，匿名注册不继承设备凭证。
- 已绑定设备正常启动不初始化蓝牙；配网时按需启动。完成后留两秒通知窗口，再等待连接、扫描与配网任务收尾，停止 NimBLE 主机后关闭蓝牙射频。GATT 对象保留用于重新开启，避免反复初始化泄漏；不释放不可恢复的控制器内存。
- 固件与服务端在线窗口为 90 秒，空杯命令有效期为 120 秒。先更新后端，再上传固件，保留 Flash。仍需真机验证熄屏/唤醒、蓝牙反复开关、断网重试与平均电流；未实现整机深度休眠。

## 6. 轻量检查与真机验收

根目录运行 `npm run test:firmware`，编译并运行实际称重、云命令 C 模块及热点测试。`firmware/test/ble_provisioning.test.mjs` 额外编译实际 C 帧解析、payload 校验、网络状态机、配置提交和旧事件读写函数，模拟网络/Flash边界，覆盖过期挑战、乱序/超限/超时帧、目标替换、严格 JSON、签名失败不联网、claim 不确定、重启只查询、Flash 失败、回滚、同主人保留空杯、转绑清杯、USB 信任配置与旧事件隔离。新增 v2 用例覆盖首次注册保存、丢失回执恢复、已有凭证保留、私网地址和旧日志读取。固定 Node 生成的公开 P-256/P1363 向量验证了签名/篡改拒绝；主机没有 mbedTLS 时该项不代表板上 crypto 执行，真实 mbedTLS 模块由 Arduino 完整构建验证编译与链接。

可运行 `npm run build:firmware` 使用已安装的 Arduino CLI / ESP32 3.3.11 完整编译；不会上传或修改开发板包。中文提示复用现有字形，数字 passkey 包含前导零；BLE 待机期间同时保留热点 SSID 和随机密码显示。

测试不证明硬件精度或浏览器兼容性。上板还须验证 BOOT 长按、10 分钟热点窗口、错误 Wi-Fi 回退、云端 TLS 与绑定、空杯执行回执、掉电恢复和记录补传，见根目录验收说明。
