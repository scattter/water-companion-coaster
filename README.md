# 饮水陪伴杯垫

用户流程：**网站注册/登录 → 蓝牙选择杯垫 → 选择 2.4 GHz Wi-Fi 并填写密码 → 自动注册并绑定 → 设置空杯 → 查看饮水记录**。0.7.2 固件支持由杯垫扫描附近网络，并保留 0.7.0 的自动注册：首次绑定时由服务端分配设备编号和凭证并写入设备；无需逐台登记、生成签名密钥或 USB 写信任公钥。设备服务地址自动下发。正式云端部署不要求用户电脑常开；本地联调时后端需要保持运行。

硬件为微雪 ESP32-S3-LCD-1.47B、TAL220B 2 kg 传感器和 3.3 V 单 VCC HX711。接线与 Arduino 设置见 [固件说明](firmware/README.md)。正常升级保留分区、编号、凭证和校准，不擦除 Flash。

## 用户首次使用

1. 用支持 Web Bluetooth 的浏览器打开正式 HTTPS 网站，注册或登录。优先使用 Android Chrome 或支持该功能的桌面 Chrome；网页会检测能力，iPhone Safari 不支持此配网方式。
2. 新机通电自动开放限时配网；已配网设备正常启动后长按 BOOT 三秒。不要按住 BOOT 上电，那是烧录模式。
3. 点击“添加杯垫”，从系统蓝牙选择器选择设备，按系统提示确认或输入杯垫屏幕上的蓝牙配对码。
4. 杯垫自动扫描附近的 2.4 GHz Wi-Fi，在列表中选择网络并输入密码；开放网络无需密码。可重新扫描，隐藏网络可手动输入。扫描功能需 0.7.1 或更新固件，旧固件保留手动输入提示。网页自动附上服务地址及短期绑定票据，设备联网后向服务端注册。
5. 等待设备联网、云端绑定和配置持久化全部完成。仅蓝牙发送成功或取得 Wi-Fi 地址不代表完成。
6. 放上自己的空杯，静置至少三秒，执行空杯设置；收到设备成功回执后再加水。

每账号同时一台杯垫。设备已属于其他账号时，必须由原账号在网页设备设置中解绑。解绑保留原用户历史，新用户看不到前任记录；新用户需要重新设置空杯。同账号换 Wi-Fi 不需要解绑，沿用设备设置中的蓝牙重新配网。

设备网页关闭后继续采样，断网记录保存在设备，云端确认后才删除。未完成工厂标定会提示联系售后，不要求普通用户准备砝码。首版不支持企业 Wi-Fi、网页认证 Wi-Fi 或固件 OTA。

## 管理员与出厂流程

完整步骤见 [出厂标定与自动注册](docs/factory-provisioning.md)。

- 工厂烧录通用固件并标定；用户首次绑定时，服务端生成唯一六位编号和独立凭证。
- 服务端通过内部硬件标识识别同一设备；已有编号、有效凭证与同主人绑定批次继续沿用。
- 正式服务地址默认取 HTTPS `APP_ORIGIN`；本地开发可自动选择唯一局域网 IPv4 的后端地址。多网卡时可由管理员指定。
- 正常注册绑定不需要管理员账号。已有身份和地址的设备重配继续使用原服务 origin，改部署入口属于受控运维。
- 工厂进行 `tare`、`calibrate` 和重量复核。用户空杯由最终用户自己设置。

管理员权限通过服务器本机 CLI 赋予指定的已注册账号，不按注册顺序自动授予：

```sh
npm run admin -- --username 已注册账号
```

上述命令须在正确的 `DB_PATH` 环境中运行。数据库需要受控备份，不提交 Git。旧版手工登记、清单导入与 provision CLI 已移除；已有设备身份和历史保留，新设备统一通过 BLE 自动注册。已部署的旧签名配网及中断恢复仍兼容。

## 日常功耗策略（0.7.2）

称重持续约 10 Hz；重量相对上次活动累计变化至少 5 g 或短按 BOOT 时唤醒屏幕。静置 30 秒关闭背光，配网与传感器/存储异常时保持亮屏。活动期间心跳 5 秒，静置后 30 秒，事件独立及时上传；心跳失败按 5、10、20、40、60 秒退避。HTTP 复用同源连接，蓝牙按需启动，配网完成或窗口结束后停止主机协议并关闭射频；长按 BOOT 可再次开启。

服务端同步采用 90 秒在线窗口、120 秒空杯命令有效期，升级固件时需同步更新并重启后端。当前没有整机深度休眠，实际电流和续航须上板测量。

## 本地开发与部署

Mac 陪伴客户端位于 `client/`，在顶部状态栏播放水豚动画并显示饮水量，点击后打开详情和设置；支持配置服务地址，使用同一套线上账号与饮水数据。使用、开发和检查说明见 [客户端说明](client/README.md)。

使用 Node.js 24。已有 `.env` 时保留，不覆盖原有凭证。首次准备：

```sh
npm ci
cp .env.example .env
npm run dev
```

Mac 用 Chrome / Edge 打开 `http://localhost:5173` 或 `http://127.0.0.1:5173`。浏览器允许本机 localhost 使用蓝牙；局域网 IP 的 HTTP 网页仍不属于安全上下文。直接在网页点击“添加杯垫”，无需先在 Mac 系统蓝牙列表中找到设备。

非生产模式下，后端自动选择唯一可用的局域网 IPv4，给设备下发例如 `http://192.168.1.10:3001`。电脑与杯垫须互通，后端监听 `0.0.0.0:3001`；多网卡时在管理员“配网服务器设置”中填写实际地址。设备地址不能使用 localhost、网页端口 5173 或 `/api` 路径。局域网 HTTP 用于开发联调，正式部署仍使用 HTTPS。

生产提供 HTTPS 网站与同源 `/api`，使用单实例 Node 后端、持久 SQLite。Compose 部署见 [容器部署说明](deploy/README.md)。

```dotenv
NODE_ENV=production
APP_ORIGIN=https://你的域名
DB_PATH=/持久目录/coaster.sqlite
```

0.7.0 自动注册无需设置 `PROVISION_SIGNING_KEY_FILE` 或 `PROVISION_DEPLOYMENT_ID`。已有旧固件使用签名时保留对应配置；私钥与数据库固定公钥不一致仍会被拒绝。

旧设备可保留折叠的“热点配网 + 八位码”兼容入口，前提是设备已有服务器身份与地址。旧固件需升级到 0.7.0 才能自动注册，不再额外写入信任配置。后端路由更新需要重启 Node 服务，仅 Vite 热更新不足以生效。

## 检查与验收

```sh
npm run check
npm run build:web
npm run test:firmware
npm run build:firmware
```

`build:firmware` 使用本机 Arduino CLI 和 esp32 3.3.11，按 S3、16 MB Flash、OPI PSRAM 完整编译，不执行上传。输出在忽略的 `data/build/esp32s3` 中。

构建网页后，`npm run smoke:web` 可在 `http://127.0.0.1:4137` 启动隔离演示：使用临时数据库和测试签名，不读取生产 `.env`，终端会显示仅供本机演示的管理员账号。这个入口不用于部署。

自动化包括独立数据库/API、蓝牙传输替身和固件模块测试；实际配对、Wi-Fi/BLE 共存、断电恢复、屏幕及称重精度需要真机验收。执行记录及边界见 [验证记录](docs/validation.md)。

协议见 [云端协议](docs/protocol.md)、[BLE 自动注册 v2](docs/ble-provisioning-v2.md) 与 [旧版 v1](docs/ble-provisioning-v1.md)。清水按 1 g≈1 ml 估算，只凭重量不能区分倒水与喝水，喝完直接补水只记录净变化。断电前从未校时的记录保留为待确认时间，不擅自算入联网当天。
