# 饮水陪伴杯垫

交付链路：**热点配网 → 杯垫主动连接云端 → 用户注册／登录 → 输入绑定码 → 登记空杯 → 网站查看记录**。网页不扫描局域网，不需要用户电脑常开，也不提供 USB 调试或重量标定入口。

硬件为微雪 ESP32-S3-LCD-1.47B、TAL220B 2 kg 传感器和支持 3.3 V 的单 VCC HX711。接线与 Arduino 设置见 [固件说明](firmware/README.md)。已有事件、校准和设备配置保留原存储格式；升级时不要擦除 Flash，也不要更换已有设备的编号或凭证。

## 用户首次使用

1. 杯垫通电，首次使用会开启 Water- 热点；屏幕显示每台独立的热点密码。
2. 手机连接该热点，提示无互联网时选择保持连接。用系统浏览器打开 **http://192.168.4.1**，选择普通 **2.4 GHz Wi-Fi** 并填写密码。
3. 按页面提示等待重启与连接。新网络连接成功才保存；失败会回退此前的网络配置。杯垫区分 Wi-Fi 连接和云端连接，不能只凭“配置已提交”认定联网成功。
4. 杯垫连上云端后，显示短时有效的 **8 位绑定码**。码过期后可在配网页重新获取。手机切回正常网络，再打开部署好的正式网站。
5. 注册账号或登录，输入绑定码。绑定码五分钟有效、仅使用一次；首版一个账号绑定一台杯垫，一台杯垫只能归属一个账号。
6. 放上自己的空杯、静置至少三秒，在网站“设置”中点击空杯设置。无需称杯子或填写克数；等待设备确认成功后再加水。

未完成出厂标定的设备会提示联系售后，不会要求用户准备砝码。网页关闭后设备继续采样；网站从云端读取状态和记录，离线时显示最后同步时间，不把旧重量当实时读数。

## 更换 Wi-Fi

杯垫正常启动后，**长按板载 BOOT 配网键 3 秒**，开启十分钟临时热点，再按上述本地配网流程填写新网络。不要按住 BOOT 再通电，那是固件下载模式。

换网只改变 Wi-Fi 配置，保留设备 ID、设备密钥、账号归属、出厂标定、空杯和饮水记录。新网络连接失败约 45 秒后回退旧配置，可重新进入配网重试。普通断网会自动重连，不会自动开放热点；断网记录待联网后补传。首版支持普通密码或开放的 2.4 GHz 网络，不含企业认证及网页认证网络。

## 本地开发

使用 Node.js 24；已有 `.env` 时保留，不覆盖凭证。首次准备：

```sh
npm ci
cp .env.example .env
npm run dev
```

开发网页为 **http://127.0.0.1:5173**，API 为 3001。开发也需要注册／登录和绑定，原来的无账号本机仪表盘入口已关闭。开发启动器不再强制共享设备凭证。已有 `.env` 的 `DEVICE_ID`／`DEVICE_TOKEN` 用于把原联调设备首次登记进设备表，已有记录保留；不会覆盖数据库中已存在的凭证。

新设备使用下面的出厂注册流程。真实杯垫开发联调可使用电脑私网 IPv4 的 HTTP 地址；生产必须用 HTTPS。网站的 `APP_ORIGIN` 是浏览器访问的源，设备的服务器地址是它能访问到的 API 所在源，两者在本地开发可能不同。

## 出厂注册与重量标定

在交付整机前由开发者完成，每台独立执行。工厂工具不会连接或写入实物 USB，输出的 JSON 由操作员在 Arduino 串口监视器发送。

1. 在云端数据库所在主机登记设备，确保 `DB_PATH` 与运行服务使用同一文件：

   ```sh
   npm run provision -- --id coaster-0001 --url https://你的域名
   ```

   工具生成独立随机设备密钥，登记设备并输出一条 `server` 串口命令。此输出含密钥，仅供出厂写入，不放到网页、二维码、截图或公开日志。已有编号会拒绝重复注册，不会静默更换密钥。具体可用参数以工具的帮助／错误提示为准。

2. 上传固件时保留整个工程和 `partitions.csv`，关闭“擦除全部 Flash”。115200 波特率、换行发送工厂工具输出的 `server` JSON；等待 `ok: true`。生产地址必须是正常证书的 HTTPS 源，不含路径。
3. 整机安装完成，保持承重上盘、移走其他物体，稳定三秒后发送 `{"cmd":"tare"}`。
4. 放上已知重量，稳定后发送 `{"cmd":"calibrate","grams":500}`，将 500 改成实际克数（50–2000 g）。用其他已知重量及偏心放置复核，记录本台验收结果。
5. 发送 `{"cmd":"status"}` 确认 `calibrated=true`，断电重启复核参数保留。空杯留给最终用户登记；不要用工厂测试杯代替用户杯。
6. 杯垫交付前保持未绑定；工厂不要替用户绑定账号。身份、服务器地址和校准准备完毕后，用户只需配网与空杯设置。

`tare`／`calibrate` 是工厂和维修串口能力，不通过用户网页或热点 API 开放。`tare` 仅供工厂修正零点，保留既有比例与空杯；重新执行 `calibrate` 会清除空杯登记。两者均不作为用户日常操作。更换用户杯子只执行 `cup`；重启不自动把正在放着的杯子归零。

## 线上部署

提供同一个 HTTPS 域名：静态网页由 Web 服务器托管，`/api/` 反向代理到本项目 Node 后端。首版后端用持久 SQLite，使用单个实例与持久磁盘；不是只上传前端静态文件就能工作。

生产配置至少包括：

```dotenv
NODE_ENV=production
APP_ORIGIN=https://你的域名
HOST=127.0.0.1
PORT=3001
DB_PATH=/持久目录/coaster.sqlite
APP_TIMEZONE=Asia/Shanghai
```

- 安装依赖后使用 `npm run build:web` 生成 `web/dist`，部署该目录；使用 `npm start` 启动 API。以上为部署操作说明，本次代码修改不会自动构建、部署或启动服务。
- 反向代理与 API 运行在同一主机，将 `/api/` 原路径转发到 `127.0.0.1:3001`，保留与 `APP_ORIGIN` 对应的原始 `Host`；`Origin` 仅原样透传，不为设备请求补填。代理须用实际客户端地址覆盖 `X-Forwarded-For`（例如 Nginx 的 `proxy_set_header X-Forwarded-For $remote_addr`），不能透传客户端自报值。生产入口仅信任来自 `127.0.0.1`／`::1` 的代理，以便按真实客户端限速。网站与 API 同源；设备也访问该 HTTPS 域名，不使用用户家庭私网 IP 作为云控制地址。
- 工厂登记与 API 必须连接同一数据库；更换数据库文件会使已有账号、设备归属和密钥不可用。正常升级先备份数据库，迁移由应用创建新表完成，旧记录不删除。
- 保留现有设备凭证才能继续接收旧设备数据；不要把一份密钥烧进所有设备。
- 正式网站使用安全 Cookie 会话；所有统计、撤销和命令按当前用户的设备归属检查。空杯设置由设备在心跳中领取并回执，网页不会直接访问家庭局域网。

容器部署见 [deploy 说明](deploy/README.md)：`docker compose` 启动 API 与网页两个容器，SQLite 放在命名卷。容器里反向代理不在同一网络命名空间，必须用 `TRUST_PROXY` 声明可信网段（宿主机部署默认为 `127.0.0.1`／`::1`），否则按 IP 限流会把所有用户算成同一个地址。

接口与状态约定见 [协议](docs/protocol.md)。公开注册使用账号名和密码，当前没有邮件／短信找回、设备转让或解绑入口；这些不会影响同一用户换 Wi-Fi。

## 检查与验收边界

```sh
npm run typecheck
npm test
npm run test:firmware
```

这些是静态检查、独立数据库／HTTP 注入、固件实际函数与模拟驱动测试；不代表真机、烧录或生产验收。实际执行结果见 [验收记录](docs/validation.md)。交付前需验证手机热点切换、绑定码过期、换网回退、断电记录保留、设备执行回执、称重精度与生产 HTTPS。

清水按 1 g ≈ 1 ml 估算；只凭重量无法区分倒水和喝水，喝完直接补水只能得到净变化。断电前从未校时的记录保留为时间待确认，不擅自算入联网当天。
